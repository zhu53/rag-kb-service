## 四、标准答案

### 靶 1 · 标准洋葱图

```
请求 →
① ServerErrorMiddleware      Starlette 自带      未捕获异常 → 纯文本 500
② TraceMiddleware            项目 add_middleware  日志/耗时/X-Trace-Id
③ AsyncExitStackMiddleware   FastAPI 自动        yield 依赖的 teardown 在这层
④ ExceptionMiddleware        Starlette           把"登记过"的异常翻译成 Response
⑤ Router（选路）→ 依赖解析（solve_dependencies）→ handler 函数体
← 响应（逆序穿回，①②③④ 都过一遍）
```

三种错误的生成点：
- **404 / 405** → ⑤ 选路阶段抛 `HTTPException`，由 ④ 的**默认**处理器接（项目没注册 `HTTPException` handler）
- **422** → ⑤ **依赖解析阶段**（`solve_dependencies` 在 `run_endpoint_function` **之前**），由 ④ 里注册的 `handle_validation` 翻译。**不是 handler 运行时**
- **500** → ① 生成，那时 ②③④ 已全部被异常炸出栈

**不做会怎样**（422 归属错了的代价）：会以为"参数校验失败发生在业务代码里"，于是把校验逻辑写进 handler 手工 if——而框架在依赖解析阶段就拦完了；还会误判 422 时事务/依赖的状态（依赖已经跑过了）。

### 靶 2 · 404（三问）

1. 404 由 **Router 选路阶段**抛 `HTTPException(404)`，不是 handler 抛的。
2. TraceMiddleware **看得到**，日志 `status: 404`——因为 ④ 已把它翻译成正常 Response，② 拿到的是响应不是异常。
3. 响应体 `{"detail": "Not Found"}`。**为什么不是 `{"code":40400,...}`**：`create_app` 只注册了 `AppError` / `RequestValidationError` / `IntegrityError` 三个 handler，`HTTPException` **没注册** → Starlette 默认处理器接管 → 逃出统一外壳。

**不做会怎样**：前端 `unwrap()` 必须多兜一种形状；监控按 `code` 字段统计错误率时，404/405 全漏。

### 靶 3 · ValueError（四问）

1. `ValueError` → ④ 的 handler 表没有它 → `_exception_handler.py:53 raise exc` 原样抛 → 穿出 Router / AsyncExitStack → 被 ② 的 `except Exception` 接住 → `logger.exception` 记 `request_failed` → **`raise` 继续抛** → 穿出 ② → ① 兜底。
2. `except` 分支**跑了**：日志有 `request_failed` + 完整 traceback。
3. `X-Trace-Id` **没有**。设 header 的代码在 **`else` 分支**，`raise` 了就走不到。**能记 ≠ 能改**。
4. 500 由 `ServerErrorMiddleware` 生成，body 是**纯文本**，`content-type: text/plain`。

**不做会怎样**：排查线上 500 时，客户端拿不到 trace_id，日志对不上请求；前端 `res.json()` 直接炸（text/plain 不是 JSON）。

**取舍点（追问 ③ 的答案）**：想在 ② 里给 500 也发 JSON + trace_id，必须在 `except` 里自己构造 Response 返回——但那等于把 500 处理权从 ① 挪到 ②，① 的兜底日志就没了，且必须保证自己不漏异常。默认不动它，知道代价即可。

## 五、差距一句 + 重写指引

> **差距**："被包装过" ≠ "统一了"。包装只认登记在册的类型；没登记的 `HTTPException` 和未知异常各有各的形状。

**重写指引**：3 分钟重画洋葱图，这次必须在图旁写出**三种响应的实际形状**（`{"detail":...}` / `ApiResponse` / 纯文本 `Internal Server Error`）。写不出来 = 还是没懂。

**追问链**：
1. 404 为什么不算 500？（`HTTPException` 是预期内的控制流，默认处理器认识它）
2. 500 为什么用不了 `ApiResponse`？（① 在最外层，它不认识你的模型）
3. 想让 500 也带 JSON 外壳 + trace_id，怎么办、代价是什么？（最外层纯 ASGI 中间件吞异常 → ① 兜底日志没了）
4. `AsyncExitStackMiddleware` 为什么必须在 ④ 里面？（`yield` 依赖的 teardown 要在响应发出前跑完）
