## 一、passlib 与 bcrypt 5.0 的兼容事故（活体复现）

| 探针 | 读数 | 结论 |
|---|---|---|
| `pip show passlib` | 1.7.4，在 `.venv/Lib/site-packages/` | 已从 pyproject/uv.lock 移除（grep 0 次），但**环境里还赖着**；security.py 第 9/15 行还在 import |
| `CryptContext(schemes=["bcrypt"])` 初始化 | **成功**，不炸 | 教材写"初始化即失败"，实测是**延迟爆炸** |
| 首次 `ctx.hash("x"*300)` | `ValueError: password cannot be longer than 72 bytes` + `bcrypt has no __about__` | 炸点在**第一次真正调用**——门禁跑 import 不触发，绿着漂到线上首次注册才炸 |
| 原生 `bcrypt.hashpw(b"x"*300, gensalt(12))` | `ValueError: ... truncate manually` | 5.0 **不再静默截断**，超长直接 raise |
| `verify_password("x"*300, 合法哈希)` | `False` | try/except 兜住 → 登录路径安全；注册路径靠 schema 字节校验拦 |

**闭环动作**：`uv sync` 抽走依赖 → `ModuleNotFoundError`（证明 import 真被用）→ 删两行 → 探针打出 `$2b$12$`（绿）。
**副作用**：删行时吞掉了分组空行 → ruff I001 红 → 补空行复绿。

## 二、密码哈希四条验收（交付物 2）

```
1 生成: $2b$12$ 60 字符
2 验证对: True
3 验证错: False
4 非法哈希: False
```

`$2b$` = bcrypt 标识；`12` = cost（2^12 轮）；60 字符定长；每盐不同（同密码两次哈希不同）。

## 三、25 汉字实验（判卷第 3 题还债）

```
RegisterIn(email='a@b.com', password='汉'*25) → 拦住了，错误类型: value_error
```

25 汉字 = 75 字节 > 72 字节。字符校验（`max_length=72`）放行，**字节校验**（`len(v.encode("utf-8")) > 72`）拦下 → 422 而不是让 bcrypt 炸 500。
固化回归：`tests/test_auth.py::test_25_hanzi_password_rejected_422`。

## 五、后门拆除（交付物 8）与 405 的发现

| 读数 | 值 |
|---|---|
| `POST /api/v1/dev/token`（TestClient） | **405** |
| `POST /api/v1/definitely/nope` | **405** |
| `GET /api/v1/dev/token` | **404** |
| `GET /no-such-file` | **404** |
| src/static grep `dev/token` | 0 处（只剩 main.py 一行说明注释） |

**根因**：StaticFiles 挂在 `"/"` 兜住所有未匹配路由，它对非 GET/HEAD 方法回 405。
**判据修正**：教材写"→404"，实测是"不存在的 POST 一律 405"。守门测试改成"发不出票"语义（404/405 均可，200/201/401/403/500 都算后门活着），文件名 `test_dev_token.py` 保留但内容反转成哨兵。

**真实服务器（uvicorn，非 TestClient）**：`/health` 200 / `dev/token` 405 / 注册 201 / 登录 200 返回真 JWT（`sub`=用户 id、`expires_in`=3600）/ 用该 token 打 `GET /kbs` 200。

## 六、债② 修复（交付物 9）与变异验证

**债②真身**（不是债表原写的"500"）：`kb_repo.update` 的 `if v is not None` 让 `{"description": null}` 变成**静默忽略**——200、原值不变、描述永远清不掉。

| 读数 | 修前 | 修后 |
|---|---|---|
| `PATCH {"name": null}` | 200（静默忽略） | **422** |
| `PATCH {"description": null}` | 200，值不变 | 200，GET 详情 `description: null` |
| MySQL `description IS NULL` | 0 | **1** |
| `updated_at` | 不变 | 跳了 1 秒 |

**变异验证**：把 `if v is not None` 塞回 `kb_repo` → `test_patch_description_null_actually_clears` **红**；还原 → 99 passed 复绿。

**真实服务的坑**：第一次在 uvicorn 上验，三个读数全是修前行为。原因：**进程是改代码之前启动的，没开 `--reload`**。重启后全部正确。
→ 这是"报告成功 ≠ 实际成功"的第 5 种形态：**测试绿了 ≠ 正在跑的服务变了**。

## 八、今日事故/发现汇总

1. passlib 是**延迟爆炸**（初始化不炸、首次调用才炸）——比教材写的更阴险。
2. 默认角色是 `member` 不是 `user`：代写测试时猜错，被门禁抓住（断言值必须有出处）。
3. 你删了 `dev.py` 但 `main.py` 的 import 还悬空——**跨文件删除要按依赖逆序改完再删**，否则留一个起不来的中间态。
4. 405 vs 404：StaticFiles 兜底改变"不存在路径"的状态码，判据得跟实测走。
5. 长驻进程不感知代码变化：`pytest 绿` 与 `服务在跑新代码` 是两件事。
