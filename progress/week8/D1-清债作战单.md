## 债 ①：IntegrityError → 409（30min）

- **现状**：重复建同名 KB，数据库抛 `IntegrityError`，API 返回 500。
- **验收标准**（判什么不给怎么写）：
  - `POST /kbs` 重名 → **409**，返回体里能看出"名字冲突"而不是"服务器炸了"；
  - 变异验证：把翻译逻辑删掉 → 相关测试必须红；
  - 说得出：为什么是 409 不是 400？**409 = 请求本身合法但和资源当前状态冲突**。
- **提示（卡 10 分钟再看）**：在 `exceptions.py` 注册 handler 或在 handler 里 try；`IntegrityError` 不止一种（唯一冲突/外键/非空），**先用探针打印真实报错信息再决定怎么区分**。

## 债 ②：PATCH null 撞 NOT NULL（20min）

- **现状**：`PATCH /kbs/{id}` 传 `{"title": null}`，走到 repo 的 `setattr` 写进 SQL，撞 NOT NULL → 500。
- **验收标准**：
  - null 字段：要么 422（schema 层拒绝）、要么按"忽略该字段"处理（二选一，**写清选了哪个、为什么**）；
  - 测试覆盖这个 case。
- **提示**：Pydantic v2 里区分"没传"和"传了 null"用 `model_fields_set`（W6-D3 学过）；决策依据是接口语义——PATCH 是部分更新，null 表达"清空"还是"没传"？

## 债 ③：竞态 rowcount 化（45min，今天的硬骨头）

- **现状**：`kb_repo.update` 用 ORM `setattr` + flush。并发下两个事务都基于旧值改 → ORM 按"匹配行数"校验，抛 `StaleDataError` → 500。（D6 探针实测过）
- **验收标准**：
  - update 改成**显式 UPDATE 语句 + 检查 `rowcount`**：rowcount == 0 时抛 404（行没了）而不是静默成功；
  - 说得出：为什么这能消灭 StaleDataError——**显式 UPDATE 是当前读 + 原子执行，不再依赖 ORM"我改的行还在"这个假设**；
  - 现有 update 相关测试全绿；变异验证：把 rowcount 检查删掉，构造"改不存在行"的测试必须红。
- **提示**：`update(...).where(...)` 后 `.execution_options(synchronize_session=False)`；`result.rowcount` 才是"数据库说我真改了几行"——**判据来自返回值，不来自"没报错"**。

## 债 ④：updated_at 返回旧值（20min）

- **现状**：update 后返回给客户端的 `updated_at` 是**内存对象的旧值**（D7 闭卷第 1 题你漏的那条）。
- **验收标准**：PATCH 后 response 里的 `updated_at` 与数据库一致；测试断言这一点。
- **提示**：修完 ③ 顺便解——显式 UPDATE 后要么 re-select，要么 `RETURNING`（MySQL 8.4 支持 `UPDATE ... RETURNING` 吗？**先实测再写结论**）。

## 债 ⑦：返回体形状统一（60min，动面最大）

- **现状**：前端 `unwrap()` 兜着三种形状（有的裸数据、有的带包裹、有的只有 data）。
- **W8-D4 巡检实测补充（2026-11-26，TestClient 跑出）**：错误路径至少有**三种**响应形状——
  1. `AppError` / 422 / 409 → `ApiResponse` 外壳 ✅
  2. 404 / 405（`HTTPException` 未注册 handler）→ Starlette 默认 `{"detail":"Not Found"}`
  3. 未捕获异常 → `ServerErrorMiddleware` 纯文本 `Internal Server Error`（text/plain，前端 `res.json()` 直接炸）
  统一范围决策要在动手前定：只统一 2/3，还是连同成功路径一起进 envelope。
- **验收标准**：统一 envelope 后，`unwrap()` 退化为恒等或删除；所有 API 测试过；前端页面一键演示仍通。
- **提示**：envelope 三件套 `{code, message, data}`；用 `response_model` + 统一依赖/装饰器实现，**不要在每个 handler 手工包**——那会变成 12 处复制粘贴。404/500 的统一如果做，注意：接管最外层会失去 `ServerErrorMiddleware` 的兜底日志（取舍见 `总结/巡检W6-中间件异常顺序-判卷.md` 靶 3）。
