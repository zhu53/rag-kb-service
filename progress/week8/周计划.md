# W8 周计划 · 用户表 + RBAC + refresh token（鉴权升级）

> 路线图原定条目（`学习路线-24周.md:131-135`）：JWT vs Session、OAuth2 密码流（FastAPI 内置）、密码哈希（bcrypt/argon2）、RBAC 权限模型、常见漏洞（SQL 注入/越权/SSRF/文件上传/CORS/限流）、练习：多租户 tenant 隔离。
> **本计划对上述条目做了重排与增删**——逐条对照见文末「§与路线图的偏差对照」。其中两个模块是路线图漏掉的前置：`users` 表（否则 RBAC 无处落）和 refresh token（鉴权闭环必需）。
> **关键任务**：把 `security.py` 里躺了一周的 `hash_password`/`verify_password` 接上真实用户；删掉 `dev/token` 演示端点。

## 本周主线问题

> **"你的 `Bearer token` 只验了签名。但签名谁都能搞到——`dev/token` 端点就在那里给任何人发合法 token。'验 token' 和 '验人'差在哪？"**
>
> W6 你学会了 Depends 的解析链，W7 你学会了把数据放进 MySQL。这两样拼起来就是本周的答案：**`get_current_user_id`（只信 token 里的字符串）升级为 `get_current_user`（拿着这个字符串去查库，验存在、验封禁、取角色）**。
> 本周结束的标准：**封禁一个用户后，他手里的 access token 还没过期，但下一个请求必须 401——你能说清这条链路上每一步是谁在检查。**

- **「本周学的东西删掉，项目会不会变差？」**——删掉 `get_current_user` 查库那步，封禁功能就静默失效 = 真落了。
