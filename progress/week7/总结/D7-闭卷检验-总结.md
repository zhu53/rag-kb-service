## 二、判档复盘（每题一句差距 + 锚点）

1. **第 1 题 4 档**：全周最扎实的一题。补一句——回滚不是"抛异常就发生"，是 `get_db` finally 的 `close()` 触发（未提交事务隐式回滚）。谁在保证回滚？**get_db**。
2. **第 2 题 3 档**：归因错误要警惕——"区分度高的列放最左"是启发式，本 query 的硬判据是**等值条件列必须最左**（查询形状）。判断题的答案要落在判据上，不是直觉上。
3. **第 3 题还债成功**：首答两处错是同一个错误的两面（以为 SELECT 是当前读 → 推出 +2）。锚点：**普通 SELECT 读快照；只有 UPDATE/DELETE/FOR UPDATE 才是当前读。丢失更新 = 两个事务基于同一条快照各自算出"过期的新值"。**追问链延伸：B 的 UPDATE 是当前读、读到的已是 27，为什么还写过期值？——因为 B 算好的 `27` 在它自己 BEGIN 之前就定死了，UPDATE 只是替它把常量写进去。
4. **第 4 题 2 档**：1101 对了；1553 记反了。一句话钉死：**外键不能动，动的是顺序——先建复合索引再拆单列，任何时刻 FK 列至少一个索引在。**
5. **第 5 题 2 档**：机制大意对，缺"优先级"这个词。路由顺序 = 匹配优先级，StaticFiles 挂 `/` 是兜底通配——顺序即契约。
6. **第 6 题补背版（30 秒，日课抽查用）**：覆盖率不能信工具口头表态——pytest-cov 打印 FAIL 但从不设退出码，`--fail-under` 按四舍五入比较（94.75→95 放过），所以门禁自己读 `coverage json` 精确浮点比。测试不能自造 app——override 打在 conftest 的 app 实例上，new 一个新的就绕过；本地有 .env 指真库就偷偷绿，CI 没有就炸。**本地绿要先问：这条绿来自哪个依赖。**

## 三、30 秒答案集（检验日专供：本周最容易被面试官问的 6 条）

1. **一条 SQL 从 handler 到落库经过谁**：TraceMiddleware → handler（Depends(get_db)）→ service → repo → autobegin 首条 SQL 开事务 → service `_commit()` → finally close。
2. **flush vs commit**：flush=翻译成 SQL 发给库、未提交、本会话可见；commit=提交、跨连接可见。
3. **并发读改写**：都基于同一条快照算，后提交覆盖先提交，最终只 +1；修法=原子 UPDATE 下推。
4. **索引列序**：查询形状决定——等值列最左、范围/排序跟后；区分度是次级启发不是主判据。
5. **迁移失败**：DDL 隐式提交无回滚，forward fix；1553 规矩=先建后拆。
6. **门禁**：判据来自数据（coverage json 精确浮点），改完故意破坏验证会红；测试隔离不能靠"记得加装饰器"。

## 六、可以讲成故事的三段

1. **我以为并发是安全的，纸笔让数字说话**。首答"两个事务各 +1，最终 +2"。重画时间轴：两个 SELECT 都读到 26，各自算出 27，B 后提交覆盖 A——最终 27，只 +1。教训：**判断必须落在"谁基于什么算的"，机制没实测过就不许当默认真**。
2. **我背了列名，没背判据**。索引题写出 DDL、说出看 type/key/rows——追问"为什么 kb_id 在前"我答"区分度最高"。实际判据是查询形状：等值列不最左，created_at 的有序性根本用不上。教训：**面试官追的就是"为什么"，归因错误在第二问就露底**。
3. **我不知道的东西恰好是最贵的**。第 6 题白卷，但补背版只有两句话：打印不等于拦截、本地绿要问来源。教训：**最该内化的知识往往是当天刚付过学费的——事故当天就写 30 秒版，别攒到验收日**。
