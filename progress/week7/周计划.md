## 本周主线问题

> **"W1-W6 你的数据一直躺在 Python 的 dict 里——它不是数据库。这一周要回答三个问题：谁管连接和事务、表怎么设计才不别扭、查得慢到底慢在哪。"**
>
> 具体三条，答不出来就是没学懂：
> 1. **一条 SQL 从 handler 里发出到结果回来，中间经过了谁？**（D1）
> 2. **给定"文档-分块-向量"三张表和一个查询，你能不能说出它走不走索引、为什么？**（D3）
> 3. **两个人同时改同一个知识库的 `doc_count`，最终值对不对？为什么会错？**（D4）
>
> 本周结束的标准：**给你一条慢查询，你能用 `EXPLAIN` 指出它为什么慢、加哪个索引、加完再 `EXPLAIN` 验证。**

**三个角色分工：**

| 用途 | 用什么 | 为什么 |
|---|---|---|
| 跑逻辑、单测 | **SQLite 文件库**（`tmp_path`） | 毫秒级、零清理；`pytest` 不该依赖"服务有没有起" |
| 索引 / 锁 / 隔离级别 / `EXPLAIN` | **MySQL 3307** | 只有真库有这些现象（SQLite 的 `EXPLAIN` 没有 `type`/`rows`/`key`） |
| W12 向量检索 | Postgres + pgvector（**到时再装**，5432 不冲突） | 项目最终形态，`pyproject` 已预留 `psycopg` |

**为什么不装 Docker**：Windows 上要 WSL2/Hyper-V + 管理员 + 镜像源，装完还要处理"容器连宿主"的网络问题；
zip 版解压即用，`mysqld --console` 的错误直接打在终端——**学习期能看见错误比"环境像生产"重要**。

**一个必须诚实说明的取舍**：单测跑 SQLite、生产跑 MySQL 是业界常见妥协（快），但它**会漏方言差异**（字符集、`GROUP BY` 宽松度、`RETURNING`、`UPDATE ... LIMIT`）。
所以本周规矩：**凡是"跟数据库行为有关"的验证（索引、锁、隔离级别、约束）一律在 MySQL 上做，SQLite 只承担"逻辑对不对"。**
