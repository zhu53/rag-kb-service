## 一、规则（从 W7-D7 起执行）

1. **每周 D7 必须填一张本表**：本周每个知识点 → 落在哪个文件哪一行。**写不出文件名+行号 = 不合格，不许开新周。**
2. 只允许三种状态：
   - **已落**：给 `文件:行号`，且能 grep 到；
   - **不需要**：写清为什么这个项目用不上（不是"以后再说"）；
   - **顺延**：指定周次 + 触发条件（例：retry → W14 接真 LLM 时落）。
3. **"我学完了""练习跑通了"不算证据**。练习目录可以删掉，主线项目必须留下痕迹。
4. 开新周的前置条件：上周核销表里**没有状态为空的行**。

## 四、为什么会出现这种断法（根因，值得写进周总结）

1. **练习线与主线是两条线**：练习做完就过，主线一直"以后某周再说"；而"以后"没有 owner。
2. **周内每一天都在加新东西，没有一天在收口**：D1~D5 每天都有交付物，但交付物是"知识点落地"，不是"项目闭环"。
3. **验收指标选错了**：W4 的验收是"覆盖率 ≥80%"，W6 是"读源码"，W7 是"三张表 + 一条迁移"——**都能在不通链路的情况下满分**。指标不指向"能演示"，就一定会长出"漂亮但断开的零件"。
4. 我的责任：W6 收尾时我没有要求你做"Depends 进项目"的核销，于是 W7 又重演了一次——同一类问题连犯两周，说明它不是偶发，是流程缺环。

**修正后的验收口径**：每周最后一天问一句——**"这周学的东西，删掉它项目会不会变差？"** 不会变差，就说明它没进项目。
