# 纸笔本用法（2026-11-07 起）

> 起因：用户提出「单看教程记不住，有点像死记硬背」，并主动买了本子和笔。
> **定位：纸笔不是"把电子笔记再抄一遍"，它是唯一不能复制粘贴的输出通道。**
> 一句话：**电子记"我查得到的"，纸笔记"我必须想得起来的"。**

## 一、为什么纸笔能治死记硬背（机制，不是感受）

| 打字/看教程 | 纸笔 |
|---|---|
| 快。快就能滑过去，眼睛扫过一段觉得"嗯懂"，其实只是**再认** | 慢 5 倍。慢下来会卡在某个词上，那个词就是你没懂的地方 |
| 可以复制。复制等于搬运，脑子不参与 | 必须从记忆里**提取**，提取不出来立刻现形 |
| 画图很麻烦，于是跳过结构，只记文字 | 画图是纸的默认动作，连错一条线自己就看见了 |

死记硬背的本质是**只有输入、没有输出**。纸笔补的是输出，而且是一种**会当场报错**的输出。

## 二、每天四件事（全部从现有时间里置换，不新增总时长）

### ① 合上书，画一张图（2 分钟 / 次，每天 1–3 次）

读教材时，每读完 2–3 节就合上书，凭记忆画当天的核心结构。**画完再打开教材，用另一种颜色的笔改。**

- 为什么非得纸笔：图是**空间关系**（谁包着谁、箭头朝哪、哪层先碰到）。打字时会退化成写文字列表，等于没画。
- 判据：**有第二种颜色的改动痕迹**才算做了。一张全对的图，八成是照着描的。
- 每天画什么：看当天教材的主结构。W6 举例——D1 依赖树（节点/箭头/后序执行）、D2 四层洋葱 + 两条路径、D3 校验→序列化数据流、D4 路由版本化分层。

### ② 闭卷三句（3 分钟 / 天，手写替代口述）

当天主线的三个机制，各写一句「定义 + 一个故障场景」。**限定词必须写出来**（"默认 scope 下""同一个 callable"）。

- 为什么改手写：口述可以含混滑过去（"大概就是缓存那个东西"）；写下来含混立刻现形，而且写的过程会自动压缩。
- 这条专治「绝对化表述」：写的时候能看见自己漏了"默认"两个字。
- **注意**：日课里的**八股 5 分钟 + 面试 5 分钟仍然是口述，不改**——那练的是嘴（面试现场要开口）。纸笔只管主线的理解检查。

### ③ 手写代码骨架（10 分钟 / 次，每周 2 次）

白板靶：不查资料，把一段关键代码的**结构**写出来。缩进、签名、控制流必须对，变量名可以简写，不要求能跑。

- 为什么：2027 秋招现场是白板/纸，没有 IDE 补全、没有 AI。手写会逼你记结构而不是拼写。
- 只写「AI 给错了你能看出来」的那部分（分层、鉴权、事务、夹具、中间件骨架），样板 CRUD 不写。
- W6 靶子：`yield` 依赖的写法、`dependency_overrides` 夹具、`TraceMiddleware` 的 `try/except/raise`。

### ④ 错题两栏（遇到就写，30 秒，不强制每天）

本子右页画两栏：

| 我当时怎么想的 | 实际是什么 |
|---|---|
| "key 不含实参，所以 `Depends(f, x=1)` 和 `Depends(f)` 只跑一次" | 参数换不了只能换 callable，key 第一项就变了 → 跑两次 |

- **左栏是重点**，右栏可以只有半句。左栏那个"错误版本"才是面试时脱口而出的东西。
- 什么时候写：**发现自己答错的那一刻**，不要等收工。收工补记的基本都是编的。

## 三、本子怎么排（物理层面，越简单越能坚持）

```
从前往后                从后往前
─────────────          ─────────────
11-07 D2               白板靶：TraceMiddleware
[图]                   [手写代码，留白可反复练]
三句：
  1. ...
  2. ...
  3. ...
错题：| 我以为 | 实际 |
```

- 每页顶部只写 `日期 · 主题`，一页一天，**写不满就留白**（留白是给自己回看用的）。
- 三种颜色够用：黑=正文，蓝=改错，红=当天最后悔的一条。
- 不用做目录、不用抄教材标题、不用写"学习心得"。**本子里出现的每一笔都必须是"我想出来的"。**

## 四、和电子笔记的分工（避免重复劳动）

| | 纸质本 | 电子（`DN-阅读笔记.md` / `DN-源码笔记.md` / `DN-总结.md`） |
|---|---|---|
| 性质 | **现场**（草稿、半句话、图、代码骨架） | **归档**（可检索、可当面试手册） |
| 要求 | 丑、快、不完整都行 | 结构完整 |
| 什么时候写 | 学习过程中 | 收工时 |
| 搬什么 | — | 只搬"值得留的 3–5 条"，**不全搬** |

- 阅读笔记 §一「原来想错的」：**先在纸上写**，电子版每 2–3 天归档一次（反而比现在天天打字省力）。
- 源码笔记：仍然电子（要贴行号），纸上只画调用链示意。
- 每日总结：仍然电子（它是面试手册，不是草稿）。

## 五、一次学习时段的完整流程（3 小时，纸笔只占约 12 分钟）

不是"额外抽时间做纸笔"，而是把笔放在键盘旁边，在三个固定位置插进去：

| 时段 | 做什么 | 纸笔动作 |
|---|---|---|
| 00:00–00:20 | 算法 20min | 先用笔在纸上写思路/画一个小用例（数组、指针位置），再敲键盘。**纸上改比 IDE 里删改快** |
| 00:20–01:05 | 读教材第一块（§一~§四） | 读完一个"概念块"→ **合上书，画图 2 分钟** |
| 01:05–01:10 | 休息 | — |
| 01:10–02:10 | 读第二块（§五~§九） | 同上：概念块结束画第二张图（2 分钟） |
| 02:10–02:40 | 读第三块 + 跑实验 | 卡住/猜错的地方 → 纸上写半句话（不打断阅读，30 秒） |
| 02:40–02:45 | **闭卷三句** | 合上全部文件，手写三句，写完再翻教材对照 |
| 02:45–02:55 | 白板靶（每周 2 次） | 手写一段代码骨架 |
| 02:55–03:00 | 错题两栏 | 只写当天最疼的那一条 |

**三个插入点记住就够**：概念块结束 → 画图；全部读完 → 三句；收工前 → 错题。

判断"概念块"的标准：教材里一个 `###` 小节讲完一件事，就是一块。D2 里 §三（洋葱结构）、§四（异常三条路）、§五（BaseHTTPMiddleware）各是一块。

## 六、每一步具体怎么写（拿 D2 当示范）

### 6.1 第一笔：只写页头

```
11-07 · D2 中间件与异常
```

就这一行。不写标题、不写目录、不写"今天学习目标"——那些都是抄，不是想。

### 6.2 画图：从里往外画，三步

大多数人画不出来，是因为从最外层开始画，一上来就要决定"谁包谁"，脑子转不过来。**反过来画**：

1. **先画最里面**：`⑥ 依赖 + 路由函数`。这是唯一确定的东西（你的 `list_kbs` 就在这）。
2. **一层层往外套框**，每套一层在框里写一行"这层负责什么"：
   - `④ ExceptionMiddleware` —— 翻译 AppError / 校验错误
   - `③ TraceMiddleware` —— 记日志、算耗时
   - `① ServerErrorMiddleware` —— 兜没人管的异常，造 500
3. **最后画路径**，用两种线：
   - 实线箭头：响应，**从 ⑥ 一层层穿回最外**（每层都过手）
   - 虚线箭头：异常，**从 ⑥ 往外飞，谁没 handler 就穿透谁**（③ 在这里被炸掉）

画完合上教材对照，**用蓝笔改**。改动痕迹就是这张图的价值；一张全对的图八成是照着描的。

**画不出来时的降级**：只画框和名字，箭头先不画。能画出"一共四层、谁在里面"就已经 70 分。

### 6.3 三句：用固定句式，逼出限定词

句式：**「X 是 ___，因为 ___。如果不 ___，就会 ___。」**

| | 例子（D2 第一句：执行顺序） |
|---|---|
| ❌ 含糊 | 中间件是洋葱模型，先进后出。 |
| ✅ 合格 | 后 `add` 的中间件在最外层，因为 `add_middleware` 是 `insert(0)` 插到列表头、构建时又 `reversed` 从尾开始包，**最后包的在最外**。所以 `A> B> handler <B <A`，谁也不含谁。 |

差别在哪：合格版有**具体名字**（`insert(0)`、`reversed`）+ **因果连接**（因为…所以…）+ **可检验的现象**（那串日志顺序）。

自检两条，缺一条就重写：
1. 句子里有没有一个**具体的东西**（函数名 / 状态码 / 参数名）？没有就是在说套话。
2. 有没有**限定词**？"默认 scope 下""同一个 callable""在 `BaseHTTPMiddleware` 里"——你之前两次答错都是漏了它。

### 6.4 代码骨架：三层填法，不写注释代替代码

以 `TraceMiddleware.dispatch` 为例（`core/logging.py:86-108`）：

**第一层：只写签名和缩进**

```python
class TraceMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        ...
```

**第二层：填控制流骨架**（这一步是全部价值所在）

```python
        start = ...
        try:
            response = await call_next(request)
        except Exception:
            ...
            raise
        ...
        return response
```

写到这里要能回答：为什么 `logger.info` 在 `try` **外面**？因为异常路径已经 `raise` 走了，能走到下面的只有正常响应。

**第三层：填关键调用**（`logger.exception` 的参数名、`status_code` 取哪个属性）

写错也没关系——**手写的目的是让"结构记在手上"，不是让代码能跑**。跑是键盘的事。

### 6.5 错题两栏：左栏写原话，右栏只写事实

| 我当时怎么想的（原话） | 实际是什么 |
|---|---|
| "响应头都发出去了，改 `status_code` 肯定没用" | `BaseHTTPMiddleware` 是**攒完再转发**：`call_next` 返回时 start 还没发，`dispatch` 返回后才发。实测改成 418 生效 |

两条规则：
- **左栏不许美化**。写"我以为 key 不含实参所以只跑一次"，不要改写成"我误解了缓存粒度"——后者是总结，前者才是你脑子里的东西。
- **右栏只写事实**，不写"正确做法"。做法容易变成抄教材。

### 6.6 归档：每周日 10 分钟，只搬 3–5 条

翻本周纸页，挑最值得留的几条，打进对应电子文件：

| 纸上的东西 | 搬到哪 |
|---|---|
| 错题两栏里最疼的 1–2 条 | 当天 `DN-总结.md` 的「踩坑实录」 |
| 「原来想错的」 | `DN-阅读笔记.md` §一 |
| 画错的图 | 不搬。图留在纸上，电子版只写一句话结论 |

**不要每天搬。** 每天搬就又变成打字劳动了。

## 七、每周日 5 分钟自查（防止变成形式主义）

翻一遍本周的纸页，只数一件事：**用蓝笔改过的地方有几处。**

- 0 处 → 这周不是在提取，是在抄。下周把"合上书画"的间隔缩到每节一次。
- 3 处以上 → 机制在起作用，继续。
- 顺手做一件事：把红笔那条抄进周总结的「踩坑实录」。

## 八、判据一句话

> 一个知识点，如果不能在纸上 3 分钟内画出它的结构、或写出它的代码骨架，就是没懂——**"我读完了"不算证据，"我写出来了"才算。**

## 九、每周一次结构图（20 分钟，本周最后一天开场）

每天的小图是**局部**（今天的机制长什么样），一周下来会有 5–8 张碎片。碎片之间什么关系、哪个是主干，只有一张全景图能回答。周总结是文字，按知识点逐个讲；**图回答的是另一件事：它们在同一条时间线上的位置。**

### 9.1 画法：一条主线 + 挂点

**不要**按知识点列表画思维导图——那只是把目录抄一遍，看着整齐，什么都说明不了。

正确画法三步：

1. **先定本周的主线**：一条"某个东西从开始到结束"的路径。
   | 周 | 主线 |
   |---|---|
   | W6 中间件/依赖 | 一个 HTTP 请求，从进来到出去 |
   | W7 事务 | 一次写操作，从开始到提交或回滚 |
   | W8 缓存 | 一次查询，从看缓存到回源 |
   | W9 鉴权 | 一次带凭证的请求，从解析 token 到放行或拒绝 |
2. **把本周每个知识点挂到它在主线上的位置**——挂在"它生效的那一刻"，不是挂在"它是哪一章"。
3. **挂不上去的单独放一边**。那些是孤立知识：要么没懂，要么本周没讲透。

### 9.2 流程（20 分钟）

| 步 | 谁做 | 时间 | 做什么 |
|---|---|---|---|
| 1 | AI | 2 min | 给图题：本周知识点清单（**打乱顺序**）+ 主线名 |
| 2 | 你 | 10 min | 纸上一张图：主线横着画，知识点往线上挂 |
| 3 | AI | 5 min | 判：哪条挂错位置、哪条漏了、哪些挂不上 |
| 4 | 你 | 3 min | 一句话说清主线："一个请求在 W6 里经过了 __ 个阶段" |

**打乱顺序是关键**：按章节顺序给，你只会顺着抄；打乱了，你必须自己决定"它属于哪一段"。

### 9.3 判据

- 全部挂上、位置对 → 本周通了
- 1–2 个挂错 → 正常，这两个就是 D7 闭卷重点
- **2 个以上挂不上 → 那几个是背的**，回教材重读那一节，不要往下走

### 9.4 和电子文件的关系

图只留纸上。电子版只存一句话：**主线是什么 + 哪几个挂错了**，写进周总结的「知识地图」一节。**不搬图**（搬图就是描图，白费时间）。

### 9.5 为什么这个格式能复用 24 周

"一条主线 + 挂点"不依赖具体技术：事务、缓存、鉴权、消息队列，全都能写成"某件事从开始到结束"。到了 W14 学 RAG，主线就变成"一个问题从进来到拿到带引用的答案"——所有 AI 工程化的知识点（切分、召回、重排、幻觉、降级、成本）照样能挂上去。

**能挂上去的知识才是你的；挂不上去的，只是你读过。**
