# W4-D4 教材：异步测试（零基础版）

> 本教材假设你**完全不会** async/await 和异步测试。所有术语第一次出现都会解释。
> 所有代码在本机实测过（Python 3.11 / pytest 9.1.1 / pytest-asyncio **1.4.0** / httpx 0.28.1），输出为真实运行结果。

---

## 0. 痛点场景：TestClient 明明能测 async 接口，为什么还要学异步测试

打开你项目里的 `tests/test_kb_api.py`，里面有这么一条：

```python
def test_chat_stream_sse(client):
    resp = client.post("/api/v1/chat", json={...,"stream": True})
    assert "data: [DONE]" in resp.text
```

`client` 是 `TestClient`——**同步**的。可 `chat` 接口是 `async def`，`RagService.answer` 也是 `async def`。同步的客户端怎么调得动异步接口？

答案：TestClient 内部偷偷起了一个事件循环，把异步调用"包"成同步的给你用。方便，但代价是三个：

**痛 1：你没法直接 await。**
想测 `RagService.answer(...)` 这个**协程**本身（不经过 HTTP），TestClient 帮不上忙——它只会发请求。你只能起服务、发请求、看响应，一条业务规则的测试被迫走完整链路。

**痛 2：异步特有的错误，TestClient 看不见。**
比如"忘记 await"——`await` 漏写时，你拿到的是一个**协程对象**（coroutine），它什么都没执行。TestClient 走 HTTP 时这错不会出现（框架负责 await），但你写单元测试时漏 await 就是真事故。更糟的是：**漏 await 的测试会绿着**（下面实测给你看）。

**痛 3：异步依赖、异步 fixture 全部测不了。**
现代 FastAPI 项目的依赖常是 `async def`（你的 `get_current_user_id` 就是）。想替换它做鉴权测试、想写 `async with` 管理生命周期的 fixture，同步 TestClient 体系下没有自然的写法。

> **一句话**：TestClient 让你"能用同步方式测异步应用"，但也挡住了异步测试的三种基本能力：直接 await、异步 fixture、异步依赖替换。今天补上。

## 1. 最小可跑示例（5 分钟亲手跑）

新建 `kb-service/tests/test_async_demo.py`：

```python
"""我的第一个异步测试。"""

import pytest
from httpx import ASGITransport, AsyncClient

from kb_service.core.security import create_access_token
from kb_service.main import create_app


@pytest.fixture
async def async_client():
    """async fixture：yield 前后各有一段异步生命周期。"""
    app = create_app()
    transport = ASGITransport(app=app)
    async with AsyncClient(
        transport=transport,
        base_url="http://test",
        headers={"Authorization": f"Bearer {create_access_token('11111111-1111-4111-8111-111111111111')}"},
    ) as client:
        yield client


async def test_health_async(async_client):
    resp = await async_client.get("/api/v1/health")
    assert resp.status_code == 200
    assert resp.json()["status"] == "ok"
```

跑它：

```powershell
cd kb-service
./.venv/Scripts/python.exe -m pytest tests/test_async_demo.py -v
```

真实输出：

```
tests/test_async_demo.py::test_health_async PASSED
============================== 1 passed in 0.05s ==============================
```

**逐行解读：**
- `async def test_health_async(...)`：测试函数本身是协程。**你没有加任何 marker**（没写 `@pytest.mark.asyncio`），它照样被正确执行——因为你项目的 `pyproject.toml` 里写了 `asyncio_mode = "auto"`（第 82 行）。auto 模式下 pytest-asyncio 会把所有 `async def` 的测试自动接管。
- `@pytest.fixture async def async_client()`：**fixture 也可以是 async**。同样因为 auto 模式，用普通的 `@pytest.fixture` 装饰器就够了。
- `AsyncClient(transport=ASGITransport(app=app))`：这是今天的主角。**不启动服务器、不开端口**，直接按 ASGI 协议把请求喂给你的 app 对象。等于"进程内 HTTP"。
- `1 passed in 0.05s`：和同步的集成测试一个量级（你的 21 个集成测试也是 0.01~0.4s）。**异步测试不会更慢**——它省掉的是真实网络和端口，不是时间。

跑通了就继续。这条示例里已经包含了今天要讲的 4 个核心部件：async test / async fixture / ASGITransport / AsyncClient。

## 2. 概念逐层展开

### 2.1 事件循环：单线程里的"调度员"

先建立最小心智模型，不然后面全是空中楼阁。

**同步代码**：函数调用是一层压一层，遇到 `time.sleep(3)` 就整条线程卡 3 秒，什么都不能干。

**异步代码**：有一个叫**事件循环（event loop）**的调度员，手上一张任务表。任务是"可暂停的函数"（协程）。调度员跑一个任务，遇到 `await`（意思是"我要等一个慢操作"）就把它挂起、去跑别的任务，等慢操作完成了再回来接着跑。

```python
async def f():
    await asyncio.sleep(1)   # 挂起：调度员去干别的，1 秒后回来
    return 1
```

三个关键事实（后面每个坑都从这里长出来）：

1. **协程只有被 await（或交给事件循环）才会执行。** `f()` 单独写一行，只是造出一个协程对象，一行代码都没跑。这就是"忘记 await → 测试照绿"的根源。
2. **事件循环是单线程的。** 在协程里写 `time.sleep(3)`，调度员自己也被卡住了——所有任务一起停。这就是"异步代码里不能用阻塞调用"的原因。
3. **一个事件循环 = 一套任务上下文。** 两个循环里的对象一般不通用（把 A 循环里的连接拿到 B 循环里用，报错 "attached to a different loop"）。

### 2.2 pytest 是同步运行器，pytest-asyncio 负责搭桥

pytest 本身只懂"调用函数、看有没有抛异常"。它拿到一个 `async def` 的测试函数，`t()` 一下得到的只是协程对象——不跑。

`pytest-asyncio` 这个插件做的事：**给每个 async 测试开一个事件循环，把协程丢进去跑**，再收集结果。

你项目用的是 `asyncio_mode = "auto"`（`pyproject.toml`）——**所有 async 测试和 async fixture 自动接管，不用写 marker**。

> 另一种模式是 `strict`：每个 async 测试必须显式标 `@pytest.mark.asyncio`。auto 适合"整库都是异步测试"，strict 适合"混着来、要求显式"。你项目用 auto，所以今天所有示例都**不写 marker**。

`--strict-markers`（你 addopts 里开了）只影响"未注册的自定义 marker"，不影响 pytest-asyncio 的 auto 行为。

### 2.3 TestClient vs AsyncClient + ASGITransport

| | `TestClient`（你现在用的） | `AsyncClient(transport=ASGITransport(app))` |
|---|---|---|
| 调用方式 | 同步 `client.post(...)` | `await client.post(...)` |
| 背后怎么跑 app | 内部起事件循环，把调用包成同步 | 直接按 ASGI 协议调用 app（`scope/receive/send`） |
| 能不能配合 async fixture / async 依赖 | 很别扭 | 天然支持 |
| 能不能直接 await service 方法 | 不能 | 能（这就是单元测试要的） |
| 启动服务器/端口 | 不需要 | 不需要 |

**ASGI 是什么**：FastAPI 应用本质是一个 `async def app(scope, receive, send)` 函数——"给我请求描述（scope），我给你发消息的通道（send），你自己去读请求体（receive）"。ASGITransport 就是按这个约定造一个假的"HTTP 客户端"，把请求喂给 app，把 app 发的消息收回来，包装成 `httpx.Response`。**没有 socket、没有端口、没有真实网络。**

**为什么用 httpx 的 AsyncClient 而不是 FastAPI 自带的 TestClient**：因为我们需要 `await`，而 TestClient 的设计是同步的（它内部那个循环不给你用）。

### 2.4 async fixture：生命周期里有了"等待"

fixture 你 D1 已经吃透了：setup 进、teardown 出，作用域决定生命周期。异步世界里多了两件事：

```python
@pytest.fixture
async def async_client():
    app = create_app()
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as client:
        yield client          # ← yield 之前：异步 setup（进入了 async with）
                              # ← yield 之后：异步 teardown（退出 async with，关闭连接池）
```

- **async fixture 也遵守 yield 的三段式**：yield 前 setup、yield 出值、yield 后 teardown。
- **teardown 需要 await 时**（比如 `await conn.close()`），async fixture 就能表达；同步 fixture 表达不了。
- **作用域照旧**：function/module/session 都可以写。你 D1 学的洋葱模型、LIFO 顺序全都不变。

**一个实测结论（和网上很多教程说法不同）**：pytest-asyncio **1.4.0** 下，`@pytest.fixture(scope="session")` 的 async fixture 直接可用，**没有** "attached to a different loop" 报错——我实测了"session 级 async fixture 持有 AsyncClient，被两个 function 级测试用"这个经典翻车场景，**3 passed**。很多 0.x 时代帖子让你写 `@pytest_asyncio.fixture(loop_scope="session")`，在 1.4 下不需要。**结论以本机实测为准**，这也是 D2 那条规矩：技术断言先实测。

### 2.5 异步依赖注入：`dependency_overrides`

你的 `get_current_user_id` 是 `async def`。测鉴权相关的分支时，两种打法：

**打法 1：真实 token（你现在 conftest 的做法）**

```python
headers={"Authorization": f"Bearer {create_access_token(str(USER_ID))}"}
```

优点：连 JWT 解码一起测了。缺点：想测"token 无效"就得造坏 token；想跳过鉴权专注业务时甩不掉。

**打法 2：覆盖依赖（FastAPI 官方口子）**

```python
import kb_service.api.deps as deps_module

async def fake_user() -> UUID:
    return USER_ID

app.dependency_overrides[deps_module.get_current_user_id] = fake_user
```

- key 是**被覆盖的依赖函数对象本身**（不是字符串、不是路径）。
- value 可以是同步函数，也可以是 `async def`——FastAPI 两种都认（实测都通过）。
- **必须在用完后 `app.dependency_overrides.clear()`**：这是**全局共享**的字典，不清会污染后续测试。用 fixture 包起来最稳（见练习骨架）。

### 2.6 测 SSE 流式接口：`async for` 消费

你的 `/chat` 接口 `stream=True` 时返回 `StreamingResponse`，内容是 `text/event-stream`（SSE）。同步 `TestClient` 只能拿到"全部攒完的 text"；异步客户端可以**边收边断言**：

```python
async with client.stream(
    "POST", "/api/v1/chat",
    json={"kb_id": str(kb_id), "question": "RAG 是什么", "stream": True},
) as resp:
    assert resp.status_code == 200
    text = "".join([part async for part in resp.aiter_text()])
assert "[DONE]" in text
assert "检索" in text
```

三个要点：
- `client.stream(...)` 是 `async with` 上下文（流要显式打开/关闭）。
- `resp.aiter_text()` 是**异步迭代器**，用 `async for` 消费——和 D1/W2 学的普通迭代器是同一套思想，只是每次取值要等 IO。
- 断言 `[DONE]` 哨兵 + 内容关键词，两条一起：只断 `[DONE]` 说明"流结束了"（可能是空流），只断内容说明"有内容"（可能没正确结束）。

### 2.7 测 async generator 本身

`RagService.answer_stream` 是**异步生成器**（`async def` + `yield`）。不经过 HTTP 直接测：

```python
chunks = [c async for c in svc.answer_stream(kb_id, user_id, "问题", top_k=5)]
assert chunks[-1] == "data: [DONE]\n\n"
```

**关键认知**：异步生成器**被迭代时才执行**（惰性，和普通生成器一样）。仅调用 `svc.answer_stream(...)` 得到生成器对象；`[async for]` 才开始跑。所以"忘记消费"的测试也是假绿——又一个"不执行也绿"的形态。

## 3. 机制：一次异步测试的完整生命周期

```
pytest 收集到 async def test_x
   ↓（asyncio_mode=auto → 自动加 marker）
pytest-asyncio 为它创建/复用一个事件循环
   ↓
在循环里跑 fixture setup（async fixture 也是协程，同理 await）
   ↓
在循环里跑测试协程：遇到 await 就把控制权交给循环
   ↓
测试结束 → 逆序跑 teardown（async teardown 同样在循环里 await）
   ↓
汇总结果（异常/断言失败/警告）
```

**"忘记 await"时发生了什么**：测试协程里 `svc.answer(...)` 造出一个协程对象 → 没人跑它 → 断言很可能对着这个对象做（`assert coro is not None` 之类）→ 绿。循环结束时 Python 的垃圾回收发现"协程从未被 await"，在 stderr 打一条 `RuntimeWarning`——**但 pytest 默认不把它升成错误**（你的 `filterwarnings` 只把 `DeprecationWarning` 升级为 error），所以**测试照样全绿**。实测：

```
tests/test_d4_verify2_tmp.py::test_forgot_await PASSED
RuntimeWarning: coroutine 'RagService.answer' was never awaited
3 passed, 2 warnings in 0.13s
```

**这就是今天最该记住的一条**：异步测试的"绿"比同步测试更不可信，因为**没被执行的协程不报错**。

## 4. 易错点表

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 忘记 `await` | 测试**绿**，stderr 有 `coroutine ... was never awaited` | 断言前问自己"我拿到的是协程还是结果"；CI 里可加 `-W error::RuntimeWarning` |
| 2 | 异步测试里用 `time.sleep()` | 测试不报错但巨慢；并发断言永远串行 | 用 `await asyncio.sleep()` |
| 3 | 异步测试里用同步 `requests` / 同步 `TestClient` 混搭 | 阻塞事件循环，fixture 可能挂住 | 统一用 `httpx.AsyncClient` |
| 4 | `AsyncClient` 不用 `async with` | 连接/资源不释放；警告 "Unclosed client" | `async with AsyncClient(...) as c:` |
| 5 | `dependency_overrides` 用完不清 | **后续测试全部**用假用户，甚至顺序一换就红 | fixture 里 clear，或 `try/finally` |
| 6 | 覆盖依赖时 key 写字符串 | 覆盖不生效，测试仍走真实鉴权（可能 401） | key 用**函数对象**（`deps_module.get_current_user_id`） |
| 7 | 测试 async 生成器却忘了消费 | 绿，但生成器里的代码一行没跑 | `[x async for x in gen]` 或 `async for` 走一遍 |
| 8 | 只断言 `[DONE]` 或只断言内容 | 空流也能过 / 流没结束也能过 | 哨兵 + 内容**两条都断** |
| 9 | 在 async 测试里 new 一个 `TestClient` 并 `.post()` | 能跑但把两套机制混在一起，fixture 语义混乱 | 异步测试一律 AsyncClient |
| 10 | 用 `@pytest.mark.asyncio` 又开 auto 模式 | 无害但多余；strict 模式才需要 | auto 模式不写 marker |

**骨架**（`# TODO` 处自己填；卡住找我，一次一层）：

```python
"""RAG 链路异步测试：单元层直接 await，集成层 AsyncClient + ASGITransport。"""

    def list_by_kb(self, kb_id: UUID, offset: int, limit: int):

        "chunk_count": 1,
        "created_at": now,
        "updated_at": now,

@pytest.fixture

    app = create_app()

async def test_answer_no_sources(monkeypatch):
    svc = RagService(doc_repo=FakeDocRepo())
    monkeypatch.setattr(svc, "kb_service", FakeKBService())
    # TODO: await svc.answer(...)，断言 sources == [] 且 answer 含"没有找到"
    ...

    svc = RagService(doc_repo=repo)
    monkeypatch.setattr(svc, "kb_service", FakeKBService())
```

## 8. 面试问法

### Q1：怎么测 FastAPI 的异步接口？TestClient 和 AsyncClient 怎么选？（30 秒）

> "两条路。TestClient 是同步的，内部起事件循环把调用包成同步，适合纯 HTTP 集成测试、上手最快；但配合异步 fixture、异步依赖替换很别扭，也没法直接 await service。所以我的项目里：集成层用 `httpx.AsyncClient(transport=ASGITransport(app=app))`——进程内按 ASGI 协议调用，不开端口，还能 `client.stream` 边收边断言 SSE；单元层直接 `await service.answer(...)`，连 app 都不建。"

**追问链**：
- ①"TestClient 内部怎么做到的？" → 起一个事件循环，把 ASGI 应用当协程跑，请求/响应通过内存通道传递。
- ②"为什么异步测试容易假绿？" → 忘记 await 时拿到的是协程对象，没被执行也不报错（只有 RuntimeWarning），断言对着对象也能过。所以我用 `-W error::RuntimeWarning` 兜底。
- ③"async fixture 的 teardown 怎么写？" → `async with` + `yield`，yield 后的清理在事件循环里 await；作用域规则和同步 fixture 一样（D1 洋葱模型）。
- ④（深）"为什么不能在一个循环里创建的连接拿到另一个循环用？" → asyncio 的 Future/Task 绑定创建它的循环，跨循环 await 会报 "attached to a different loop"；生产里表现为"服务启动时把连接建在启动循环里，请求循环换了一个就炸"。

### Q2：怎么测 SSE / 流式接口？（30 秒）

> "用 `client.stream` 拿到响应，`resp.aiter_text()` 异步迭代拼起来，断言两件事：结束哨兵（我们项目是 `data: [DONE]`）和内容关键词。只断哨兵会放过空流，只断内容会放过没正常结束的流。如果测的是 async generator 本身，直接 `[c async for c in gen]`——异步生成器是惰性的，不消费就一行都不跑。"

**追问链**：①"流里要测异常路径吗？"（生成器中途抛错 → 客户端收到 500 前的部分内容/连接中断）②"怎么测客户端断开？"（取消任务 → CancelledError，生产里要正确处理避免资源泄漏）③"SSE 和 WebSocket 测试差异？"（SSE 单向、是普通 HTTP 响应；WS 要专门的测试客户端与握手）。

## 9. 闭卷自测（先做，再折叠）

1. 为什么"忘记 await"的异步测试会绿？怎么在 CI 里防住？
2. `AsyncClient(transport=ASGITransport(app))` 和 `TestClient` 的本质区别是什么？各自适合哪层？
3. async fixture 的 setup/teardown 怎么写？作用域规则变了吗？
4. `dependency_overrides` 的 key 是什么？用完必须做什么？不做会怎样？
5. 测 SSE 应该断言哪两样东西？各防什么？
6. 异步生成器"不消费就不执行"，这对测试意味着什么？
7. 为什么异步代码里不能用 `time.sleep`？
8. 我们项目用什么模式处理 async 测试（auto/strict）？要不要写 marker？

<details><summary>答案</summary>

1. 没 await 时只造出协程对象，代码没执行，断言对着对象也能过；只有 RuntimeWarning 且默认不升级为错误。防法：`-W error::RuntimeWarning`，或约定"每个异步测试必须有一条对返回值的断言"。
2. TestClient 内部起循环把异步调用包成同步；AsyncClient + ASGITransport 直接按 ASGI 协议调用 app（scope/receive/send）。集成层用 AsyncClient（能配合 async fixture/依赖、能 stream），纯快速冒烟用 TestClient 也可以。
3. `@pytest.fixture` + `async def` + `yield`，yield 后是异步清理（`async with` 内自然完成）。作用域规则完全不变（function/module/session 与洋葱模型）。
4. key 是被覆盖的依赖**函数对象**；用完必须 `app.dependency_overrides.clear()`，否则全局字典污染后续测试（顺序一换就红）。
5. 结束哨兵（`[DONE]`）防"空流"；内容关键词防"没正常结束/内容错"。两条都断。
6. 测试拿到生成器对象不代表执行；不迭代 = 生成器里的代码一行没跑，测试可能全绿但没验证任何东西。
7. `time.sleep` 阻塞线程，而事件循环就跑在这个线程上——整个循环被卡住，所有协程停摆；要 `await asyncio.sleep()`。
8. `asyncio_mode = "auto"`（pyproject.toml 第 82 行），async 测试与 async fixture 自动接管，不写 marker；`--strict-markers` 只管未注册的自定义 marker。

</details>
