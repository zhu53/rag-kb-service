## 0. 一句话主线

> **异步测试 = 同步测试思想 + 事件循环的物理约束。**
> 最大新增风险：**异步的"绿"比同步更不可信**——协程没 await，测试照样绿，只留一句 stderr 警告。

## 1. 事件循环心智模型（三个根源事实）

### 1.1 三条事实（后面每个坑都从这里长出来）

| 事实 | 内容 | 测试上的后果 |
|---|---|---|
| 单线程调度 | 事件循环是"调度员"，同一时刻只有一个协程在跑 | 测试里不会有数据竞争，但会有"谁在 await 点让出"的顺序问题 |
| `await` = 主动让出 | 协程只在 await 处把控制权交还循环 | `await` 不是"等待完成"的修饰词，是让出权 |
| 协程不 await 就不执行 | `async def` 调用只造出协程对象，不跑代码 | **漏 await = 那行代码一微秒都没执行**，且默认不报错 |

### 1.2 面试问法

**Q：Python 的 async/await 是并发吗？**
> 30 秒：是单线程并发（协作式调度）。事件循环维护一个就绪协程队列，协程在 await 处主动让出控制权，循环再调度下一个。它适合 IO 密集（等待时切出去干别的），不适合 CPU 密集（没有抢占，一个死循环协程会卡死整个循环）。

**追问链**：①"和线程的区别" → 无抢占、无 GIL 争抢、切换点显式（await）vs 系统随时切；②"死循环协程会怎样" → 卡死整个事件循环（这题能区分背过和用过）；③"asyncio.sleep(0) 干嘛的" → 主动让出一次，常见于把同步代码改成保留异步边界的占位。

## 2. TestClient 为什么不够，ASGITransport 是什么

### 2.1 定义

- `TestClient`（starlette）：同步接口打异步应用，**内部偷起一个事件循环**把 async 包成 sync。
- `AsyncClient(transport=ASGITransport(app))`（httpx）：异步测试客户端，**进程内按 ASGI 协议直接调 app**，不开端口、不启服务器。

### 2.2 为什么存在（TestClient 的三个代价）

| 代价 | 说明 |
|---|---|
| 测试函数必须是 sync | 没法直接 `await` 业务的 async 方法（RagService.answer 是协程，TestClient 里调不了） |
| async fixture 受限 | 想在 fixture 里 `async with AsyncClient(...) as c: yield c`——sync fixture 里没法 await |
| 依赖替换走的是同步路径 | async 依赖（如 `get_current_user_id`）在 TestClient 的内嵌循环里替换行为不同 |

### 2.3 怎么用（本项目定版写法）

```python
@pytest.fixture
async def async_client() -> AsyncIterator[AsyncClient]:
    app = create_app()
    transport = ASGITransport(app=app)
    async with AsyncClient(transport=transport, base_url="http://test") as client:
        yield client
```

要点：`base_url` 随便填（不走网络）；`async with` 保证 client 关闭（连接池释放）；和 D1 的 fixture 洋葱模型完全同构。

### 2.4 机制：ASGITransport 在干嘛

ASGI 是 Python 异步 Web 的标准协议：框架（FastAPI）暴露 `app(scope, receive, send)` 三个通道。`ASGITransport` 就是在进程内**直接按协议调 app**，把 httpx 的请求翻译成 scope + 消息传进去。省掉的是"起 uvicorn 端口 + TCP 环节"，保留的是全部应用栈（中间件、路由、校验、异常处理）。

### 2.5 面试问法

**Q：异步接口怎么测？为什么不直接用 TestClient？**
> 30 秒：用 httpx 的 AsyncClient 配 ASGITransport，在进程内按 ASGI 协议直接调用 app，不开端口。TestClient 是同步壳包异步，代价是测试函数没法 await、async fixture 用不了、异步依赖替换受限。ASGITransport 保留完整应用栈，只省掉网络环节，测试依然是毫秒级。

**追问链**：①"那集成测试里不也没测网络层吗？" → 对，ASGI 之下（uvicorn、TCP、反向代理）不在测试范围，那是部署验证的事；②"ASGI 和 WSGI 区别" → 异步协议、单实例处理并发连接、WebSocket 支持；③"transport 换成真 HTTP 会怎样" → 那就是起真服务做 E2E，属于金字塔顶层。

## 3. async fixture 与 pytest-asyncio

### 3.1 怎么用（本项目实测环境：pytest 9.1.1 / pytest-asyncio 1.4.0，auto 模式）

- 测试函数：`async def test_xxx()` 直接写，auto 模式自动识别，**不需要装饰器**。
- fixture：`@pytest.fixture` + `async def` + `yield`，作用域规则与同步完全一致（function/session 四档）。

### 3.2 实测结论（与网上 0.x 时代教程不同，以本机为准）

| 传言 | 本机实测（pytest-asyncio 1.4.0） |
|---|---|
| "session 级 async fixture 会报 attached to a different loop" | **不报**——session 级 async client 给两个测试用，3 passed |
| "要写 `@pytest_asyncio.fixture(loop_scope=...)`" | auto 模式下普通 `@pytest.fixture async def` 直接可用 |
| "忘记 await 测试会失败" | **测试绿**，只在 stderr 留 `RuntimeWarning: coroutine ... was never awaited` |

教训：**异步测试的版本行为差异极大，教程结论必须在自己锁定的版本下实测**。这是本项目"技术断言必须实测"约定的又一次应验。

## 4. 异步依赖覆盖：dependency_overrides

### 4.1 怎么用

```python
from kb_service.api.deps import get_current_user_id

async def _fake_user_id() -> UUID:
    return USER_ID

app.dependency_overrides[get_current_user_id] = _fake_user_id
# ... 测试 ...
app.dependency_overrides.clear()   # 用完必须清！
```

### 4.2 机制与三条铁律

1. **key 是函数对象本身**（不是字符串）——`overrides[get_current_user_id]`，FastAPI 组装依赖时按"同一个函数对象"查表。
2. **value 可以是 sync 或 async 函数**——FastAPI 会按原依赖的协程性处理。
3. **它是 app 上的全局字典**——不 clear 会泄漏到同 app 的其他测试（与 D2 的 `get_settings.cache_clear()`、D4 的 `store.pop` 同一族问题：**全局状态谁种谁收**）。

### 4.3 单元层怎么替换内部依赖（对照）

| 场景 | 手法 |
|---|---|
| 依赖是 FastAPI Depends（走路由） | `dependency_overrides` |
| 依赖是构造参数（如 `RagService(doc_repo=...)`） | 构造时传 fake |
| 依赖是类内部 `new` 出来的（如 `RagService.__init__` 里 `self.kb_service = KBService()`） | `monkeypatch.setattr(svc, "kb_service", FakeKBService())` —— **可测试性债**：W7+ 应改成构造注入 |

### 4.4 面试问法

**Q：怎么替换 FastAPI 的鉴权依赖来测接口？**
> 30 秒：`app.dependency_overrides[get_current_user_id] = fake_fn`，key 是函数对象，value 可 sync 可 async。测试结束必须 clear，因为它是 app 上的全局字典。单元层不走路由的，直接构造注入 fake 或 monkeypatch 实例属性；后者是可测试性债，正解是构造注入。

## 5. SSE 流式测试

### 5.1 怎么用

```python
async with client.stream("POST", "/api/v1/chat", json={...}) as response:
    lines = [line async for line in response.aiter_lines()]
```

### 5.2 两种读取视图（踩过的坑）

| API | 视图 | `data: [DONE]\n\n` 读出来是 |
|---|---|---|
| `aiter_lines()` | 按行切分、**吃掉换行符** | `"data: [DONE]"` + 后随空行 `""` |
| `aiter_text()` | 原始文本块 | 原样 `"data: [DONE]\n\n"` |

**断言谁，就用和谁配套的读取方式**。SSE 协议以空行分隔事件，行视图和块视图看到的世界不同。

### 5.3 断言策略

- 哨兵断言：最后一块是 `[DONE]`（流正常收尾）
- 内容断言：至少一块含 `data: `（真有业务内容）
- 两者都要：只有哨兵 = 流空了也算过；只有内容 = 断流可能测不出。

## 6. 假绿新形态：异步的绿更不可信

### 6.1 漏 await 三部曲（D4 最值钱的一条）

1. `cache.put(...)`（没 await）→ 协程对象被创建后**立即丢弃**，函数体从未执行
2. 测试继续跑，后续断言若"碰巧成立"→ **绿**
3. 唯一痕迹：stderr 一句 `RuntimeWarning: coroutine ... was never awaited`，而 filterwarnings 通常只升级 DeprecationWarning，**它不会让测试变红**

### 6.2 对策

```powershell
pytest -W error::RuntimeWarning
```

把 RuntimeWarning 升级为错误 → 漏 await 立刻变红。**CI 里应默认加这个开关**——这是"让假绿无处躲"的最便宜手段。

### 6.3 关联 D3

这其实是 D3"测试为什么没红"在异步世界的变体：同步世界假绿靠**永真断言**，异步世界多一个入口——**代码根本没执行还绿**。测试设计原则不变：先问"这条测试能杀死哪种 bug"，漏 await 的 bug 它杀得死吗（加 -W 后能）。

## 8. 30 秒答案集

1. **async 是并发吗** → 单线程协作式，await 处让出，适合 IO 密集。
2. **异步接口怎么测** → AsyncClient + ASGITransport 进程内调 app，不启端口。
3. **为什么不只用 TestClient** → 同步壳包异步，await/async fixture/异步依赖替换全受限。
4. **漏 await 会怎样** → 协程不执行，测试绿，只有 stderr RuntimeWarning；对策 `-W error::RuntimeWarning`。
5. **dependency_overrides 怎么用** → key 函数对象、value 可 async、用完 clear。
6. **SSE 怎么测** → client.stream + aiter_lines/aiter_text，断言哨兵 + 内容。
7. **async fixture 作用域** → 与同步一致；1.4.0 下 session 级实测无 loop 报错。
8. **asyncio.sleep(0)** → 主动让出一次调度。
9. **单测内部协程依赖怎么换** → monkeypatch 实例属性是短期，构造注入是正解。
10. **time.time vs monotonic** → 墙上钟 vs 单调钟；测间隔必须单调。

## 12. 闭卷自测（先自己答，再展开）

<details><summary>Q1：为什么 `AsyncClient(transport=ASGITransport(app))` 比起真服务更适合集成测试？它没测到什么？</summary>

进程内按 ASGI 协议直调 app，保留全部应用栈（中间件/路由/校验/异常处理），省掉端口与 TCP，毫秒级。没测到：ASGI 之下的部署层（uvicorn 行为、反向代理、网络超时）——那是 E2E/部署验证的事。

</details>

<details><summary>Q2：漏 await 为什么不让测试变红？怎么让它红？</summary>

协程对象创建后即被丢弃，函数体从未执行，Python 只在 GC 时发 RuntimeWarning（stderr，不是异常）；断言若碰巧成立测试就绿。对策：pytest 加 `-W error::RuntimeWarning` 把警告升级为错误。

</details>

<details><summary>Q3：dependency_overrides 的 key 是什么？为什么用完必须 clear？</summary>

key 是依赖函数对象本身（FastAPI 组装依赖时按函数对象查表）。它存在 app 实例的全局字典上，不清会泄漏到复用同一 app 的其他测试，造成跨测试污染。

</details>

<details><summary>Q4：aiter_lines() 读 SSE 流，最后一条 "data: [DONE]\n\n" 读到的是什么？为什么？</summary>

读到 `"data: [DONE]"`，且末尾还会跟一个空行 `""`——aiter_lines 按行切分并吃掉换行符。要拿原始块（含 `\n\n`）得用 aiter_text()。断言谁就得用配套的读取视图。

</details>

<details><summary>Q5：TTL 缓存用 time.time() 算 deadline 有什么隐患？应该用什么？</summary>

time.time() 是墙上时钟，NTP 校时/手动改时间会回拨或前跳，deadline 整体漂移（该过期的不过期或提前失效）。测"经过时间"必须用 time.monotonic()——单调、不受系统时间调整影响。

</details>

<details><summary>Q6：为什么"测试之间共享全局单例 + 互不清理"是脆测试的头号来源？举两个它爆雷的触发方式。</summary>

测试结果依赖执行顺序，任何一个测试的写入都可能成为另一个测试的前提。爆雷方式：①用 pytest -k / 单跑某个用例 → 前置写入消失直接红；②对调或新增测试改变执行顺序 → 原本绿的变红。正解：每测试独立实例（fixture 造）或 teardown 清理——谁种谁收。

</details>

<details><summary>Q7：怎么测"30 分钟后过期"这种 TTL 逻辑而不真睡 30 分钟？</summary>

把时钟注入：构造函数接受 `now: Callable[[], float]`（默认 time.monotonic），测试里塞一个可拨动的假时钟——写完直接把假时钟拨过 deadline 再断言 get 返回 None。不睡真时间、不慢、不受调度抖动影响（这是 D5 的时间注入/freezegun 主题）。

</details>
