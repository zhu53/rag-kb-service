## 二、这周真正长出来的三样东西

### 1. 从"一报错就崩"到"报错是线索"

四天里你独立处理过：`NameError`（装饰器在加载时执行）、`ValidationError`（pydantic 启动校验）、500（先看服务端 traceback）、pre-commit 拦截（钩子改了文件要重新 add）。**读报错三要素**（位置 / 类型 / 信息）已经内化——这是 Week 1 唯一目标，达成了。

### 2. "验证" muscle：三次实测推翻"想当然"

- 3.11 Windows 时钟粒度 15.6ms → 排序断言静默失效（AI 参考代码自己也错了）
- `threading.local` 并发串号 9/10（不并发就测不出来，第一次实验 0/10 是假阴性）
- 无 `@wraps` → 不只是名字变了，是 **FastAPI 全接口 422**

这就是 AI 时代后端工程师的核心能力：**没验证过的结论一律存疑，包括 AI 给的**。三份证据脚本都留在 `day7_evidence/`，随时复跑。

### 3. 分层的手感（虽然理论还欠一分）

mini_kb / mini_api 亲手写过一遍 repo → service → api，真项目里一眼对上了：`get_or_403`、exception_handler、`KBOut.from_row` 全是同一套。**唯一欠的：闭卷说出"service 为什么不 import fastapi"**——W7 换 SQLAlchemy 时连本带利收回。

## 三、方法论沉淀（比知识更值钱的部分）

1. **三档阶梯**（Day6 用户主动提出）：跨度太大的任务不是意志力问题，是台阶问题。照着敲 → 讲顺 → 偷看计数 ≤3。已验证有效。
2. **第四档验收**（已固化成长期约定）：每次交付埋 3–4 个坑（≥2 个近期踩过的、≥1 个运行时零症状），找得出 = 真懂。#01 战绩 3/4 + 1 豁免。
3. **实测规范**：涉及时间/浮点/哈希/dict 顺序的结论，必须用**项目锁定的 3.11**（`kb-service/.venv`）测，不能用默认解释器想当然。
4. **推送三连自己练**：git push 由用户亲手执行，AI 只给命令块 + 只读核对。
