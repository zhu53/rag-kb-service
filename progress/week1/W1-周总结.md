## 2. 这周真正长出来的三样东西（面试可讲）

### 2.1 从"一报错就崩"到"报错是线索"

四天里独立处理过：`NameError`（装饰器在加载时执行）、`ValidationError`（pydantic 启动校验）、500（先看服务端 traceback）、pre-commit 拦截（钩子改了文件要重新 add）。

**读报错三要素**（位置 / 类型 / 信息）已经内化：
- **位置**：`in <module>` = 加载期；`in function` = 调用期——决定了"是 import 写错还是逻辑写错"。
- **类型**：NameError / TypeError / AttributeError / ValidationError 各指向一类根因。
- **信息**：消息里常常直接给答案（`name 'x' is not defined`、`Field required`）。

### 2.2 "验证" muscle：三次实测推翻"想当然"

- **3.11 Windows 时钟粒度 15.6ms** → 排序断言静默失效（AI 参考代码自己也错了）
- **`threading.local` 并发串号 9/10**（不并发就测不出来；第一次实验 0/10 是假阴性）
- **无 `@wraps`** → 不只是名字变了，是 **FastAPI 全接口 422**

**这就是 AI 时代后端工程师的核心能力：没验证过的结论一律存疑，包括 AI 给的。** 三份证据脚本留在 `day7_evidence/`，随时复跑。

### 2.3 分层的手感（理论当时还欠一分，已在 W3 收回）

mini_kb / mini_api 亲手写过 repo → service → api，真项目里一眼对上：`get_or_403`、exception_handler、`KBOut.from_row` 是同一套。
当时唯一欠的："闭卷说出 service 为什么不 import fastapi" —— W3-D4 用双 repo 对拍 + 第四档 4/4 连本带利收回。

## 3. 方法论沉淀（比知识更值钱）

1. **三档阶梯**：跨度太大的任务不是意志力问题，是台阶问题（照着敲 → 讲顺 → 偷看计数 ≤3）。
2. **第四档验收**：每次交付埋 3–4 个坑（≥2 个近期踩过的、≥1 个运行时零症状），找得出 = 真懂。
3. **实测规范**：涉及时间/浮点/哈希/dict 顺序的结论，必须用**项目锁定的 3.11** 测。
4. **推送三连自己练**：git push 亲手执行，AI 只给命令块 + 只读核对。
5. **写完每段手写代码补"30 秒面试版本"**（本周最大卡点的对策）——这条后来演化成"总结必须是面试参考版"。

## 4. 本周面试题库（20 题速答索引）

### 环境与工具

| 问题 | 30 秒答案要点 |
|---|---|
| 你怎么管理 Python 环境？ | uv + `.python-version` 锁版本 + `uv.lock` 锁全树；`uv sync` 一条命令复现；删 venv 能 5 分钟重建算验收 |
| 为什么锁 Python 版本？ | 语言行为随版本变（如实测的 3.11 Windows 时钟精度 15.6ms），跨版本行为可能不同 |
| 调试线上/本地 bug 的方法？ | 读 traceback 三要素 → 断点在异常构造处看现场 → 缩小范围（二分/日志）→ 修完补回归测试 |
| 为什么要 pre-commit？ | 把格式/lint/EOF 变成提交门槛，纪律自动化；钩子改了文件要重新 add |

### Git

| 问题 | 答案要点 |
|---|---|
| rebase 和 merge 区别？ | rebase 重写历史成线性、适合本地未推送的整理；merge 保留分叉、适合公共分支 |
| `git rebase -i` 常用操作？ | squash 合并、reword 改信息、drop 删提交、edit 拆分 |
| 冲突怎么解？ | 读冲突标记 → 明确"两边意图" → 手工合成 → 跑测试 → `git add` 继续 |
| Conventional Commits 意义？ | 类型化提交（feat/fix/refactor/docs/test/chore）便于生成 changelog、语义化版本、审查 |

### 标准库（详见 Day4/Day5 总结）

| 问题 | 答案要点 |
|---|---|
| pathlib vs os.path | 对象化、`/` 拼路径、自带读写、跨平台 |
| dataclass 可变默认 | 定义时求值共享 → `default_factory` |
| Protocol vs ABC | 结构化 vs 名义；零侵入 vs 运行期强制 |
| gather vs TaskGroup | 孤儿任务 vs 自动取消 + ExceptionGroup |
| lru_cache 坑 | 参数须可哈希、有副作用别缓存、缓存跟函数对象走 |
| deque vs list | 两端 O(1) vs `pop(0)` O(n) |

### 工程/框架

| 问题 | 答案要点 |
|---|---|
| ContextVar vs threading.local | 隔离单位：协程任务 vs 线程；asyncio 单线程下 local 串号 |
| 忘写 `@wraps` | 签名被当成 `*args/**kwargs` → FastAPI 全 422 |
| 为什么 service 不 import fastapi | 分层依赖方向；异常由最外层翻译（W3-D4 收回） |
| 500 怎么排查 | 先看服务端 traceback（不是猜前端）；`traceback.print_exc()` 给完整栈 |
| 403 vs 404 | 用户友好 vs 防枚举；产品决策，要能说权衡 |

## 5. 一条可讲的故事线（面试自我介绍素材）

> "我第一周重点补的是工程习惯。环境用 uv 管，锁 Python 版本和依赖树，保证任何机器一条命令复现；调试不打 print，用断点看调用栈和变量现场；Git 上练了交互式 rebase 整理提交、手解冲突、配 pre-commit 做提交门禁；然后花两天把标准库过了一遍，重点是 pathlib、dataclasses、asyncio、functools 和 typing.Protocol；最后用三百多行抄改了一个三层的最小项目——repo/service/api 分开、异常统一翻译成 HTTP 状态码、用 ContextVar 做请求上下文。这一周最值钱的收获是验证习惯：我实测发现 Windows 上 3.11 的时钟精度只有 15.6 毫秒，导致排序测试静默失效，连 AI 给的参考实现都是错的——所以我现在对任何没跑过的结论都存疑。"
