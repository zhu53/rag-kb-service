### P1（零症状）· `doc_stats` 的死注解
```python
def doc_stats() -> dict[str, str]:
    return {"total": len(_DOCS), ...}   # total 是 int，不是 str
```
这是**纯 Python 函数**，注解是惰性字符串，运行时**根本不检查** → 永远无症状。
对比：`stats` 路由的返回注解如果错了会 500（FastAPI 是运行时校验器）。
**这正是"注解三种命运"的第三种：没有 FastAPI 介入时，注解只是文档。**
（截至你看到这行，它已经错了"很久"——没人发现，因为它从不炸。）

### P2 · `get_doc` 的 `except Exception` 吃掉了业务异常
```python
except Exception as exc:
    raise RuntimeError(f"查询文档失败: {exc}") from exc
```
`NotFoundError` 被吞掉重包装成 `RuntimeError` → 没有 exception_handler 认识它 → **500**。
正确：查询失败应让 `NotFoundError` 原样飞出去，由统一异常层翻译成 404。
（Day7 自测 Q12 / Q10 的知识点：**接口边界谁负责翻译成 HTTP**。）

### P3 · 路由顺序：`/docs/stats` 定义在 `/docs/{doc_id}` 之后
`GET /docs/stats` 会先匹配 `/{doc_id}`，`doc_id="stats"` 查不到 → 走 P2 → **500**。
这是 Day3 你在真项目里**主动避开过**的坑（当时你说"stats 要写在 {kb_id} 之前"）。

### P4 · `trace_id = f"doc-{hash(request.url.path) % 100000:05d}"`
同一**路径**的请求永远得到同一个 trace_id——smoke 输出最后两行就是证据：
```
trace: doc-73448 doc-73448   ← 两次请求同一个 id，串号
```
和 Day6 的 `id(path)` 驻留坑同族：**用请求内容派生"唯一" ID**。
唯一 ID 必须 `uuid4()`，或者至少拼上时间戳+随机数。
