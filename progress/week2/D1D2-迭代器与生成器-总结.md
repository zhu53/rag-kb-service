## 1. 迭代器协议（一切的地基）

### 1.1 `for` 只是语法糖，背后三步

```python
for x in [1, 2, 3]:
    print(x)
```

```python
it = iter([1, 2, 3])        # ① 要一个迭代器
while True:
    try:
        x = next(it)        # ② 不断问"下一个"
        print(x)
    except StopIteration:   # ③ 问不出来就退出
        break
```

**协议只有两个方法**：

| 方法 | 谁调用 | 职责 |
|---|---|---|
| `__iter__` | `iter(obj)` | 返回一个迭代器 |
| `__next__` | `next(it)` | 返回下一个值；没有了就 `raise StopIteration` |

实现这两个方法，你的类就能被 `for` 遍历。**和 D4 的 Protocol 同一思想：只检查形状，不检查继承。**

### 1.2 为什么必须 `raise StopIteration`，不能返回 `None`

实测：`[1, None, 3]` 里的 `None` 被正常输出，没被当结束。

> **"结束"这个信号不能和数据本身撞车。** 异常是最干净的分流：正常值走 `return`，结束走 `raise`。

### 1.3 Iterable vs Iterator（最高频面试题）

| | Iterable（可迭代对象） | Iterator（迭代器） |
|---|---|---|
| `__iter__` | ✅ | ✅ |
| `__next__` | ❌ | ✅ |
| 反复遍历 | ✅（每次 `iter()` 新建迭代器） | ❌ **只能一遍** |
| 例子 | `list` `dict` `str` `set` `Cursor` | `list_iterator`、生成器对象、文件对象 |

**为什么迭代器只能走一遍**：它只有一个"内部光标"，`__next__` 每次把光标推进一格，到底 `StopIteration`，**没有 `reset()`**。list 不是自己数数——每次 `for` 都现造一个新迭代器。

实测：

```
第一次 list(it2): [1, 2, 3]
第二次 list(it2): []          ← 迭代器已被走空
list 两次都是 [1,2,3]          ← 每次新建迭代器
```

**实战坑**：把生成器传给两个下游函数，第二个永远拿到空。要用两次 → 先 `list()` 物化，或写成生成器**函数**每次调用现造。

### 1.4 手写迭代器（Countdown）

```python
class Countdown:
    def __init__(self, start: int) -> None:
        self.current = start

    def __iter__(self):
        return self            # 迭代器自己就是迭代器（一次性光标）

    def __next__(self):
        if self.current < 1:
            raise StopIteration
        value = self.current   # 先取值
        self.current -= 1      # 再减
        return value
```

**我踩的坑**：写成 `value = self.current - 1` → 多减一次 → 吐出 `[2, 1, 0]`。
**教训**：`i -= 1`（先减再返回减后的）vs `i - 1`（返回减之前的值）——倒序、索引、二分里反复出现。

## 2. 生成器

### 2.1 本质定义

```python
def countdown(start):        # 3 行 = 上面 12 行的类
    while start >= 1:
        yield start
        start -= 1
```

**一句话**：生成器是**用 `yield` 写的函数，它自动实现了迭代器协议**（`__iter__` + `__next__`）。

### 2.2 `yield` = 暂停，不是结束（四件实测事实）

```
① 调用 demo() 时函数体一行都不执行（惰性求值）
② next() → 执行到 yield → 暂停 → 送出值
③ 再次 next() → 从暂停点继续
④ 函数末尾 return 的值塞进 StopIteration.value
```

| `return` | `yield` |
|---|---|
| 函数**结束** | 函数**暂停** |
| 只能一次 | 可无限次 |
| 调用时立即执行 | 调用时什么都不做 |

**状态存在哪**：生成器的**栈帧**（和闭包同源）——局部变量在暂停期间一直活着。这也是"生成器比类省事"的原因：你不用手动把状态搬进 `self`。

### 2.3 `yield` 是双向的（协程雏形）

```python
def counter():
    n = 0
    while True:
        n += 1
        got = yield n      # 右边送出 n，左边接收外部 send 进来的值
        print(f"收到 {got!r}")

c = counter()
next(c)        # 1（第一次必须 next(None) 或 next()，不能直接 send 非 None）
c.send("hi")   # 打印 收到 'hi'，返回 2
```

这是**协程的雏形**：`yield` 让函数能在"交出控制权"和"拿回控制权"之间往返。asyncio 的 `await` 底层就是这一套（W9 深入）。

### 2.4 内存与性能（实测，200 万个数）

| | 内存 | 求和耗时 |
|---|---|---|
| `[i for i in range(N)]` | **77.36 MB** | 0.124 s |
| `(i for i in range(N))` | **0.00 MB** | **0.075 s** |

- list 要把 200 万个 int 对象**全部建出来**放进列表
- 生成器**边算边扔**，内存里同时只有一个值
- 这里生成器还更快：省掉了建 list 的开销

**什么时候不用生成器**：数据量小、需要多次遍历、需要索引/切片 → list 更合适。
**判据一句话**：**数据大不大 + 要不要重复用**。

### 2.5 能表示"无限"

```python
def naturals():
    n = 0
    while True:
        yield n
        n += 1

next(naturals())   # 0 —— 如果是 list，这行就 OOM 了
```

**"无限流"是生成器独有的能力**，也是后文分页/流式处理的前提。

### 2.6 和项目的直接联系（最重要）

```python
# kb-service/api/v1/chat.py
return StreamingResponse(
    svc.answer_stream(question),        # ← 生成器
    media_type="text/event-stream",
    headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
)
```

如果改成 list：`text = await llm.generate(...)` 等 10 秒全部生成完，然后一次性蹦出来——用户盯着空白 10 秒。
生成器版：1 秒内看到第一个字，边生成边发。

> **流式 = 生成器（边算边发）+ 暂停保住状态 + 客户端只消费一次。**
> D1 学的"只能走一遍"在流式里不是缺点，是**特性**：流本来就只有一遍。

## 3. 三个练习（3/3 全对，可直接背）

### 3.1 `read_lines` —— 逐行读大文件

```python
def read_lines(path: str) -> Iterator[str]:
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip("\n")
```

**两个细节**：
- `strip("\n")` 而不是 `strip()`：后者会吃掉行首行尾空格，而缩进代码/Markdown 列表里空格是内容
- `with` 在生成器里照样有效：生成器被 GC 或 `close()` 时，`with` 会正确关闭文件

**为什么大文件必须这样**：100 万行日志，`f.readlines()` 要几 GB 内存；生成器始终只占一行。

### 3.2 `fib()` —— 无限斐波那契

```python
def fib() -> Iterator[int]:
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b     # 元组解包：右侧先全部求值再赋值
```

**关键**：`a, b = b, a + b` 右侧**先算完**再赋值。拆成两句就错：

```python
a = b          # a 变成 1
b = a + b      # b = 1 + 1 = 2 ← a 已被改，结果错
```

### 3.3 `take()` —— 从任意 iterable 取前 n 个

```python
def take(iterable: Iterable[T], n: int) -> Iterator[T]:
    count = 0
    for item in iterable:
        if count >= n:
            break
        yield item
        count += 1
```

边界都对：`n=0` → 空；`n > 长度` → 取完就停。
标准库等价物：`itertools.islice(iterable, n)`（C 实现，更快）。

## 4. 面试问法 + 30 秒答案

### 4.1 "说一说 Python 的迭代器和生成器"

**30 秒答案**："迭代器是实现了 `__iter__` 和 `__next__` 的对象，`__next__` 用够就抛 StopIteration；`for` 循环本质就是 `iter()` 拿迭代器、反复 `next()`、捕获 StopIteration。可迭代对象只有 `__iter__`，每次 for 都现造一个新迭代器，所以能反复遍历；迭代器只有一根光标、没有 reset，所以只能走一遍。生成器是用 yield 写的函数，自动实现迭代器协议——调用时不执行，第一次 next 才跑到 yield 并暂停，栈帧保留局部变量，所以能边算边扔、省内存，还能表示无限序列。"

### 4.2 "生成器能省多少内存？"

**30 秒答案**："我实测过 200 万个数求和：list 版本占 77 MB，生成器版本 0 MB——因为 list 要把 200 万个 int 对象全建出来，生成器内存里同时只有一个值。耗时上生成器反而更快一点（0.075s vs 0.124s），省掉了建列表的开销。但生成器不能重复遍历、不能索引切片，所以数据量小或要多轮使用时还是 list 合适。"

### 4.3 "为什么流式输出必须用生成器？"

**30 秒答案**："因为要边算边发。用 list 的话必须先等模型把整段话生成完再一次性返回，用户盯着空白等十秒；生成器是每产出一个 token 就 yield 一次，框架就把它推给客户端，首字延迟降到一秒内。生成器的'只能消费一次'在这里恰好是特性——流本来就只能读一遍。工程上还要注意中间层缓冲，比如 Nginx 会把响应攒起来，需要设 `X-Accel-Buffering: no`。"

## 5. 追问链（面试深挖预演）

| 起点 | 追问 | 你要能答 |
|---|---|---|
| Iterable/Iterator | 为什么 list 能反复遍历？ | 每次 `iter(lst)` 新建一个 list_iterator，list 自己不移动 |
| 生成器省内存 | 状态存在哪里？ | 生成器栈帧；暂停时局部变量仍存活（和闭包同源） |
| generator 只能一遍 | 怎么"重放"？ | 物化成 list，或写成生成器**函数**每次调用造新对象；`itertools.tee` 也能分叉（但占内存） |
| 生成器 vs 协程 | `send` 怎么用？ | `yield` 既送值又接值，`send(x)` 把 x 塞进 `yield` 表达式；先 `next()` 启动 |
| 协程 | `yield from` 是什么？ | 把迭代/委托给子生成器，并把 send 透传下去；asyncio 前身 `@coroutine` 就基于它 |
| 性能 | 生成器一定更快吗？ | 不一定：小数据量时生成器有额外帧开销；优势在内存与首字节延迟 |
| 流式 | 中间层缓冲怎么办？ | `X-Accel-Buffering: no`、关闭 gzip 缓冲、客户端用 EventSource/ReadableStream |

## 7. 核心 API 速查

| API | 用途 |
|---|---|
| `iter(x)` / `next(it)` | 取迭代器 / 取下一个值 |
| `StopIteration` | 迭代结束信号（不能用 None 代替） |
| `yield` / `yield from` | 产出值并暂停 / 委托给子生成器 |
| `send(v)` / `throw()` / `close()` | 向生成器送值 / 抛异常 / 关闭 |
| `itertools.islice(it, n)` | 取前 n 个（C 实现） |
| `itertools.tee(it, 2)` | 把迭代器分叉成两个（缓存代价） |
| `collections.abc.Iterable/Iterator` | 用于 isinstance 判断与类型注解 |

## 8. 30 秒答案集（考前速背）

1. **for 三步** → `iter()` → `next()` → 捕 `StopIteration`。
2. **为什么用异常不用 None** → 数据本身可能合法是 None，信号会撞车。
3. **Iterable vs Iterator** → 只有 `__iter__` vs 两者都有；前者可反复遍历。
4. **迭代器为什么只能一遍** → 单光标无 reset；list 每次现造迭代器。
5. **生成器本质** → yield 函数，自动实现迭代器协议。
6. **yield vs return** → 暂停 vs 结束；无限次 vs 一次；调用时不执行 vs 立即执行。
7. **生成器省内存** → 边算边扔，栈帧保状态；实测 77MB → 0MB。
8. **流式为什么用生成器** → 边算边发，首字节延迟从 10s 降到 <1s。

<details><summary>答案</summary>
1. `iter(obj)` → 循环 `next(it)` → 捕 `StopIteration`；数据可能有合法 None，信号会撞车。
2. Iterable 只有 `__iter__`；Iterator 有 `__iter__` + `__next__`。list 是 Iterable，所以能反复遍历。
3. 单光标、单向前进、无 reset；物化成 list 或每次调用生成器函数新建对象。
4. 没执行；第一次 `next()`（或 for 的首次迭代）才执行到第一个 yield。
5. 结束 vs 暂停；一次 vs 无限；返回值进 `StopIteration.value` vs 直接交付，且 yield 可 `send`。
6. 小数据、需多次遍历/索引时别用；流式必须用因为它边算边发，首字节延迟低。
