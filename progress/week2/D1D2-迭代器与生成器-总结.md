## 一、迭代器协议

### 1. `for` 只是语法糖，背后只有三步

```python
for x in [1, 2, 3]:
    print(x)
```
等价于：
```python
it = iter([1, 2, 3])          # ① 要一个迭代器
while True:
    try:
        x = next(it)          # ② 不断问"下一个"
        print(x)
    except StopIteration:     # ③ 问不出来就退出
        break
```

**协议只有两个方法**：

| 方法 | 谁调用 | 职责 |
|---|---|---|
| `__iter__` | `iter(obj)` | 返回一个迭代器 |
| `__next__` | `next(it)` | 返回下一个值；没有就 `raise StopIteration` |

实现这两个方法，你的类就能被 `for` 遍历。**和 Day5 的 `Protocol` 同一思想：只检查形状。**

### 2. 为什么必须是 `StopIteration`，不能返回 `None`

实测：`[1, None, 3]` 里的 `None` 正常输出，没被当成结束。

> **表示"结束"的信号不能和数据本身撞车**。异常是最干净的分流：正常值走 `return`，结束走 `raise`。

### 3. Iterable vs Iterator（最高频面试题）

| | 可迭代对象 Iterable | 迭代器 Iterator |
|---|---|---|
| `__iter__` | ✅ | ✅ |
| `__next__` | ❌ | ✅ |
| 反复遍历 | ✅（每次 `iter()` 新建迭代器） | ❌ **只能一遍** |
| 例子 | `list` `dict` `str` `set` | `list_iterator` `生成器对象` `文件对象` |

**为什么迭代器只能走一遍**：它只有一个"内部光标"，`__next__` 每次把光标推进一格，到底就 `StopIteration`，**没有 `reset()`**。而 list 不是自己数数——每次 `for` 都现造一个新迭代器。

实测：
```
第一次 list(it2): [1, 2, 3]
第二次 list(it2): []          ← 迭代器已被走空
list 两次都是 [1,2,3]          ← 每次新建迭代器
```

**实战坑**：把生成器传给两个下游函数，第二个永远拿到空。要用两次 → 先转 list，或用工厂函数每次现造。

### 4. 手写迭代器（练习答案要点）

```python
class Countdown:
    def __init__(self, start: int) -> None:
        self.current = start

    def __iter__(self):
        return self          # 迭代器自己就是迭代器

    def __next__(self):
        if self.current < 1:
            raise StopIteration
        value = self.current   # ← 先取值
        self.current -= 1      # ← 再减
        return value
```

**我踩的坑**：写成 `value = self.current - 1` 多减了一次 → 吐出 `[2, 1, 0]`。
**教训**：`i -= 1`（先减再返回减后的）vs `i - 1`（返回减之前的值）——倒序/索引/二分里反复出现。

## 二、生成器

### 1. 本质：用 `yield` 写的函数，自动实现迭代器协议

```python
def countdown(start):        # 3 行，等价于上面 12 行的类
    while start >= 1:
        yield start
        start -= 1
```

**面试一句话**：生成器是用 `yield` 写的函数，它自动实现了 `__iter__` 和 `__next__`。

### 2. `yield` = 暂停，不是结束（实测四件事）

```
① 调用 demo() 时函数体一行都不执行（惰性求值）
② next() → 执行到 yield → 【暂停】→ 送出值
③ 再次 next() → 从暂停点继续往下
④ 函数末尾 return 的值，塞进 StopIteration.value
```

| `return` | `yield` |
|---|---|
| 函数**结束** | 函数**暂停** |
| 只能一次 | 可无限次 |
| 调用时立即执行 | 调用时什么都不做 |

**状态存哪**：生成器栈帧（和闭包同源）——局部变量 `n` 在暂停期间一直活着。

### 3. `yield` 是双向的

```python
def counter():
    n = 0
    while True:
        n += 1
        got = yield n      # 右边送出 n，左边接收外面 send 进来的值
        print(f"收到 {got!r}")

c = counter()
next(c)        # 1（第一次必须 next(None)，不能直接 send 非 None）
c.send("hi")   # 打印 "收到 'hi'"，返回 2
```
这是**协程的雏形**，asyncio 底层就靠它。W9 再深入。

### 4. 内存与性能（实测，200 万个数）

| | 内存 | 求和耗时 |
|---|---|---|
| `[i for i in range(N)]` | **77.36 MB** | 0.124s |
| `(i for i in range(N))` | **0.00 MB** | **0.075s** |

- list 要把 200 万个 int 对象**全部建出来**放列表里
- 生成器**边算边扔**，内存里同时只有一个值
- 这里生成器反而更快：省掉了建 list 的开销

**什么时候不用生成器**：数据量小、需要多次遍历、需要索引/切片 → list 更合适。
**判断标准**：**数据大不大 + 要不要重复用**。

### 5. 能表示"无限"

```python
def naturals():
    n = 0
    while True:
        yield n
        n += 1

next(naturals())   # 0 —— 如果是 list，这行就 OOM 了
```

### 6. 和项目的直接联系（本节最重要）

```python
# kb-service/api/v1/chat.py
return StreamingResponse(
    svc.answer_stream(...),            # ← 生成器
    media_type="text/event-stream",
    headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
)
```

**如果改成 list**：
```python
text = await llm.generate(question)   # 等 10 秒全部生成完
return text                            # 然后一次性蹦出来
```
用户盯着空白等 10 秒 → 然后突然出现一大段。

**生成器版**：1 秒内看到第一个字，边生成边发。

> **流式 = 生成器（边算边发）+ 暂停保住状态 + 客户端只消费一次**
> D1 学的"只能走一遍"在这里不是缺点，是**特性**：流本来就只有一遍。

## 三、练习答案（3/3 全对）

### 1. `read_lines` —— 逐行读大文件

```python
def read_lines(path: str) -> Iterator[str]:
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.strip("\n")
```

**两个细节值得记**：
- `strip("\n")` 而不是 `strip()`：后者会把行首行尾空格也吃掉，而缩进代码/Markdown 列表里空格是内容
- `with` 在生成器里照样有效：生成器被垃圾回收或 `close()` 时，`with` 会正确关闭文件

**为什么大文件必须这样**：100 万行日志，`f.readlines()` 要几 GB 内存；生成器始终只占一行。

### 2. `fib()` —— 无限斐波那契

```python
def fib() -> Iterator[int]:
    a, b = 0, 1
    while True:
        yield a
        a, b = b, a + b     # ← 元组解包：右侧先全部求值再赋值
```

**关键**：`a, b = b, a + b` 右侧**先算完**再赋值。如果拆成两句：
```python
a = b          # a 变成 1
b = a + b      # b 变成 1+1=2 ← 但 a 已经被改了，结果错
```

### 3. `take()` —— 从任意 iterable 取前 n 个

```python
def take(iterable: Iterable[T], n: int) -> Iterator[T]:
    count = 0
    for item in iterable:
        if count >= n:
            break
        yield item
        count += 1
```

**边界都处理对了**：`n=0` → 空，`n > 长度` → 取完就停。
**标准库等价物**：`itertools.islice(iterable, n)`（C 实现，更快）。

## 五、闭卷自测 6 问

1. `for x in obj:` 底层三步是什么？`StopIteration` 为什么不能用返回 `None` 代替？
2. Iterable 和 Iterator 各有什么方法？list 属于哪种？为什么？
3. 迭代器为什么只能走一遍？怎么让它"能走两遍"？
4. 调用生成器函数时函数体执行了吗？第一次执行发生在什么时候？
5. `yield` 和 `return` 的三个区别？
6. 什么场景不该用生成器？为什么流式输出必须用生成器？

<details>
<summary>答案</summary>

1. `iter(obj)` 拿迭代器 → 循环 `next(it)` 取值 → 捕获 `StopIteration` 退出。因为数据本身可能有合法的 `None`，用 `None` 当结束信号会和真实数据撞车。
2. Iterable 只有 `__iter__`（能产生迭代器）；Iterator 有 `__iter__` + `__next__`。list 是 Iterable——它有 `__iter__` 没有 `__next__`，每次 `for` 都新建一个迭代器，所以能反复遍历。
3. 迭代器只有一个内部光标，`__next__` 单向前进，到底 `StopIteration`，没有 reset。要多次用它：先 `list()` 物化，或写成生成器**函数**每次调用现造一个新对象。
4. 没有执行，一行都没跑。真正的执行发生在第一次 `next()`（或 `for` 的第一次迭代）。
5. `return` 结束函数 / `yield` 暂停函数；`return` 只能一次 / `yield` 可无限次；`return` 的值进 `StopIteration.value` / `yield` 的值直接交给调用方。另外 `yield` 还是双向的（可 `send`）。
6. 数据量小、需要多次遍历、需要索引或切片时别用。流式必须用生成器，因为它是**边算边发**的：不用等全部生成完就能把第一个字节推给客户端，配合 SSE 实现逐字输出。

</details>
