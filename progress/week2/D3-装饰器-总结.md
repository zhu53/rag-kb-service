## 一、本质：`@` 只是语法糖

```python
@decorator
def foo(): ...
```
**完全等价于**：
```python
def foo(): ...
foo = decorator(foo)     # 把函数当参数传进去，返回的东西替换掉 foo
```

**装饰器 = 接收函数、返回函数的函数。** 就这一句。

## 二、闭包：装饰器的地基

```python
def make_adder(n):
    def adder(x):
        return x + n     # n 来自外层
    return adder

add5 = make_adder(5)     # 外层已返回
add5(3)                  # 8 —— n 还在，因为闭包记住了它
```

`adder.__closure__` 里能翻出那个 cell（存着 n）。

### 经典坑：闭包捕获的是变量，不是值

```python
funcs = [lambda: i for i in range(3)]
[f() for f in funcs]          # [2, 2, 2]  不是 [0,1,2]！
```

三个 lambda 共享**同一个** `i` cell，循环结束时 `i` 是 2，所以三个函数读到的都是 2。

**两种修法**：
```python
funcs = [lambda i=i: i for i in range(3)]   # A：默认参数，定义时求值复制
def make(i): return lambda: i               # B：工厂函数，每次新闭包
funcs = [make(i) for i in range(3)]
```

## 三、两层装饰器模板（本周必须会写）

```python
import functools

def 装饰器名(fn):                      # 第 1 层：接住原函数
    @functools.wraps(fn)               # 保住 __name__ / __doc__（忘加 → FastAPI 全 422）
    def wrapper(*args, **kwargs):      # 第 2 层：每次调用实际走这里
        # ① 调用前做事（日志 / 计时开始 / 权限检查）
        result = fn(*args, **kwargs)   # ② 调用原函数
        # ③ 调用后做事（日志 / 计时结束）
        return result                  # ④ 把结果还回去
    return wrapper
```

**比喻**：第 1 层 = 装修工人（进场一次装门）；第 2 层 = 防盗门（以后每次进出都经过）。

**三个必须记住的点**（每个都是真实踩过的坑）：

| 要点 | 忘了会怎样 |
|---|---|
| `@functools.wraps(fn)` | `__name__`/`__doc__` 丢失；FastAPI 把 `*args/**kwargs` 当必填 query → **全接口 422**（Day7 实测） |
| `*args, **kwargs` | 只能装饰固定签名的函数，换一个就 TypeError |
| `return result` | 被装饰函数的返回值变成 `None` |

## 四、三层：带参装饰器（看懂即可）

```python
def retry(times):                  # 第 1 层：接收装饰器参数
    def decorator(fn):             # 第 2 层：接收被装饰函数
        @functools.wraps(fn)
        def wrapper(*a, **kw):     # 第 3 层：真正调用
            ...
        return wrapper
    return decorator

@retry(times=3)                    # ← 有括号！先调 retry(3)，拿到 decorator
def flaky(): ...
```

**口诀**：`@` 后面**有括号 → 三层**（多的一层只为先把参数吃进来）；**没括号 → 两层**。

## 五、类装饰器（看懂即可）

```python
class CountCalls:
    def __init__(self, fn):
        functools.update_wrapper(self, fn)
        self.fn, self.count = fn, 0
    def __call__(self, *a, **kw):
        self.count += 1
        return self.fn(*a, **kw)
```

对象只要实现了 `__call__` 就能当函数调用，也就能当装饰器。**适合需要保存状态**（计数器、缓存）。

## 六、两个执行时机（实测）

**① 装饰在定义时执行一次，函数体在调用时才执行**
```
定义阶段：  [装饰器执行中] 正在包装 hello     ← 只一次
调用阶段：  [调用时] 进入 hello / hello 执行   ← 每次
```
与 Day4 的 `@lru_cache` 同源：**装饰器在 import 阶段就执行**，所以它用到的名字必须已导入。FastAPI 也靠这一点在启动时扫描全部路由。

**② 多装饰器：从下往上包，从上往下执行**
```python
@a
@b
def f(): ...     # 等价于 f = a(b(f))

# 输出：A 进入 → B 进入 → f → B 退出 → A 退出    （洋葱结构）
```

## 七、手写验证（timer）

```python
def timer(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        start_time = time.perf_counter()
        result = fn(*args, **kwargs)
        cost = time.perf_counter() - start_time
        print(f"[{fn.__name__}] 耗时 {cost:.4f}s")
        return result
    return wrapper
```

验收 4 项全过：耗时正确 0.1007s / 返回值 `done` 透传 / `__name__` 仍是 `slow` / 套在带参函数 `add(2,3)` 上也得 5。

## 八、注意：为什么用 `perf_counter` 不用 `time.time`

- `perf_counter()` 是**单调时钟**，专门用于测耗时，精度最高，不受系统时间调整影响
- `time.time()` 可能被 NTP 校时**往回跳**，算出负耗时
- 这也是为什么 Day6 mini_kb 里的 `now()` 要自己做单调兜底

## 九、和项目的联系

| 装饰器 | 项目里的位置 |
|---|---|
| 两层无参 | `@app.get(...)` 路由注册（本质就是"注册 + 返回原函数"） |
| `@wraps` | 所有自定义装饰器都必须写 |
| 洋葱顺序 | 中间件栈：`trace` 在最外层，`exception` 在内层 |
| 带参三层 | `@app.middleware("http")`（括号里是参数，所以是三层） |

## 十、闭卷自测 5 问

1. `@decorator` 展开成一句赋值语句是什么？
2. `[lambda: i for i in range(3)]` 里三个函数分别返回什么？为什么？怎么修？
3. 两层装饰器的 `wrapper` 里必须做的三件事？
4. `@` 后面有没有括号，决定了什么？
5. 装饰器代码什么时候执行？函数体什么时候执行？

<details>
<summary>答案</summary>

1. `foo = decorator(foo)`。
2. 都是 2。闭包捕获的是**变量（cell）**不是值，三个 lambda 共享同一个 `i`，循环结束时 i=2。修法：`lambda i=i: i`（默认参数在定义时求值）或工厂函数 `def make(i): return lambda: i`。
3. ① 调用前做事 ② `result = fn(*args, **kwargs)` 调用原函数 ③ `return result` 把结果传出去。
4. 层数。没括号 → 两层（装饰器直接收函数）；有括号 → 三层（先调用一次收参数，返回值才是真正的装饰器）。
5. 装饰器代码在**定义时**（import 阶段）执行一次；被装饰函数体在**每次调用**时执行。

</details>
