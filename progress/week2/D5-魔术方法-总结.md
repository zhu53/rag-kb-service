# W2-D5 魔术方法 + @property · 知识点总结

> 复习材料标准。所有结论 Python 3.11 实测。

## 一、语法 ↔ dunder 对照表（核心）

| 你写的语法 | Python 实际调用 |
|---|---|
| `print(obj)` / f-string `{obj}` | `__str__`，没定义退回 `__repr__` |
| 调试器 / 日志 / list 内部显示 | `__repr__`（**容器内部永远用 repr**） |
| `len(obj)` | `__len__` |
| `a == b` | `a.__eq__(b)` |
| `obj[k]` | `__getitem__` |
| `for x in obj` | `__iter__` → `__next__`（D1 已手写） |
| `with obj` | `__enter__` / `__exit__`（Day5 contextmanager 学过） |

**主线一句话**：Python 对象的行为全是协议约定的——实现对应 dunder，就获得对应语法。
D1 迭代器、D5 魔术方法、D4 异常基类，同一件事。

## 二、`__repr__` vs `__str__`

| | `__repr__` | `__str__` |
|---|---|---|
| 给谁看 | 开发者（调试器/日志/traceback/容器） | 用户（print/f-string） |
| 惯例格式 | `KB(id='kb1', docs=3)`——像能重建对象的代码 | 人类可读的描述 |
| 优先级 | **只写 repr 不写 str 时，print 也用 repr** | — |

**repr 两大纪律**：
1. **不打印大字段全文**——100KB 的 content 进日志，grep 直接废掉。用长度代替：`chars={len(self.content)}`
2. 字段用 `{x!r}` 自动加引号

## 三、`__eq__` 与 NotImplemented

```python
def __eq__(self, other: object) -> bool:
    if not isinstance(other, Doc):
        return NotImplemented     # return，不是 raise；没有括号
    return self.doc_id == other.doc_id
```

- **默认行为是坑**：不定义 `__eq__` 时 `==` 比内存地址，内容相同的两个对象也不等
- **`NotImplemented` 是协商失败信号**：返回后 Python 去问对方，两边都拒绝才退回比地址 → False。全程无异常
- 定义了 `__eq__` 的类**不可哈希**（不能进 set / 当 dict key），除非同时定义 `__hash__`
- pydantic 的模型能 `==` 比较，就是因为框架生成了 `__eq__`；`@dataclass` 也自动生成（Day5 学过）

## 四、@property：把方法伪装成属性

```python
@property
def char_count(self) -> int:
    return len(self.content)

d.char_count      # ✅ 无括号，像属性
d.char_count()    # ❌ TypeError
```

**什么时候用**：值能从其他字段**算出来**时就不存它——存两份必然不同步。
kb-service 的 `doc_count` 思路；mini_kb 的 `to_dict()` 手动算，property 让它永远正确。

## 五、本次踩的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | `__eq__` 没写 isinstance 守卫 → `Doc == "a"` 直接 AttributeError | 注释写了"不同类型返 NotImplemented"，实现却没做——**注释和代码要对齐** |
| 2 | repr 打印 content 全文 | repr 是给日志看的，大字段用长度 |
| 3 | `NotImplemented()`（如果加括号就错了） | 它是单例对象不是类/异常 |

## 六、核心 API 速查

| API | 用途 |
|---|---|
| `__repr__` | 开发者视图，必须定义 |
| `__eq__` + `isinstance` 守卫 | 按业务键判等 |
| `return NotImplemented` | 协商失败信号（无括号） |
| `@property` | 计算属性，无括号访问 |
| `{x!r}` | f-string 里调用 repr（自动加引号） |

## 七、闭卷自测（先答，再折叠）

<details>
<summary>1. 只定义 __repr__ 不定义 __str__，print(obj) 输出什么？</summary>
用 __repr__。str 缺失时 Python 自动退回 repr——所以赶时间只写 repr。
</details>

<details>
<summary>2. 两个内容完全相同的自建类对象 == 是 False，为什么？</summary>
没定义 __eq__，默认比内存地址（id）。要按内容比必须自己实现 __eq__，
或用 @dataclass / pydantic（自动生成）。
</details>

<details>
<summary>3. __eq__ 里 return NotImplemented 之后发生了什么？</summary>
Python 拿着 == 的另一边问对方的 __eq__；对方也不认识（也返回 NotImplemented）
就退回默认行为（比地址）。它不是异常，是协商信号。
</details>

<details>
<summary>4. 什么值适合做 @property？什么不适合？</summary>
能从现有字段推导的（doc_count、char_count）适合；需要 IO（查库/发请求）
或计算昂贵的不适合——属性访问看起来便宜，调用方不会预期它慢。
</details>

<details>
<summary>5. 定义了 __eq__ 后 set 存这个类的对象会怎样？</summary>
不可哈希，放进 set 直接 TypeError。需要同时定义 __hash__
（通常 hash(self.doc_id)，与 __eq__ 用同一批字段）。
</details>
