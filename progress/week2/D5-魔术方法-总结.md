# W2-D5 · 魔术方法与 @property【面试参考版】

> 日期：2026-10-23 ｜ 所有结论 Python 3.11 实测
> 主线：**Python 对象的行为全是协议约定的**——实现对应 dunder，就获得对应语法。D1 迭代器、D4 异常基类、本篇魔术方法，是同一件事的三个切面。

---

## 1. 语法 ↔ dunder 对照表（核心）

| 你写的语法 | Python 实际调用 |
|---|---|
| `print(obj)` / f-string `{obj}` | `__str__`，没定义则退回 `__repr__` |
| 调试器 / 日志 / list 内部显示 | `__repr__`（**容器内部永远用 repr**） |
| `len(obj)` | `__len__` |
| `a == b` | `a.__eq__(b)`（失败再 `b.__eq__(a)`） |
| `hash(obj)` / set / dict key | `__hash__` |
| `obj[k]` | `__getitem__` |
| `obj[k] = v` | `__setitem__` |
| `for x in obj` | `__iter__` → `__next__`（D1 已手写） |
| `with obj` | `__enter__` / `__exit__` |
| `obj(...)` | `__call__`（对象可当函数，装饰器类就靠它） |
| `bool(obj)` / `if obj` | `__bool__`，没有则看 `__len__` |
| `x in obj` | `__contains__`（没有则退化成遍历） |
| `obj + other` | `__add__` |
| `str` / `repr` 之外：排序 | `__lt__` 等比较魔术方法 / `functools.total_ordering` |

**记忆方式**：dunder 是"语法糖的落地接口"。你想要的每一种写法，背后都有一个固定名字。

## 2. `__repr__` vs `__str__`

| | `__repr__` | `__str__` |
|---|---|---|
| 给谁看 | 开发者（调试器/日志/traceback/容器） | 用户（print/f-string） |
| 惯例格式 | `KB(id='kb1', docs=3)`——像能重建对象的代码 | 人类可读描述 |
| 优先级 | **只写 repr 不写 str 时，print 也用 repr** | — |

**repr 两大纪律**：

1. **不打印大字段全文**——100KB 的 content 进日志，grep 直接废掉。用长度代替：`chars={len(self.content)}`。
2. 字段用 `{x!r}` 自动加引号（区分 `"1"` 和 `1`）。

**为什么容器内部用 repr**：`print([obj])` 走的是 list 的 `__str__`，而 list 内部对元素调 `repr`——为了让列表在调试器里可读、可复制粘贴重建。

### 面试问法："`__repr__` 和 `__str__` 的区别？"

**30 秒答案**："repr 面向开发者，目标是准确、可重建，调试器、日志、容器显示都用它；str 面向用户，目标是可读。只定义 repr 时，print 会退回用 repr，所以赶时间只写 repr 也够。生产上 repr 要注意别把大字段全文打出来——日志里塞一个 100KB 的正文，等于把日志系统废掉，用长度或摘要代替。"

## 3. 比较与哈希：`__eq__` / `NotImplemented` / `__hash__`

### 3.1 正确写法

```python
def __eq__(self, other: object) -> bool:
    if not isinstance(other, Doc):
        return NotImplemented     # return，不是 raise；没有括号
    return self.doc_id == other.doc_id
```

- **默认行为是坑**：不定义 `__eq__` 时 `==` 比内存地址，内容相同的两个对象也不等。
- **`NotImplemented` 是协商失败信号**：返回后 Python 去问对方（`other.__eq__(self)`），两边都拒绝才退回比地址 → False。**全程无异常**。
- **`NotImplemented` 是单例对象**，不是类也不是异常——写 `NotImplemented()` 就错了。

### 3.2 `__eq__` 与 `__hash__` 的联动（高频考点）

> **定义了 `__eq__` 而没有定义 `__hash__`，Python 自动把 `__hash__` 设为 `None`** → 对象不可哈希 → 放进 set / 当 dict key 直接 `TypeError: unhashable type`。

为什么这样设计：哈希表要求"相等的对象必须有相同 hash"。你自定义了"相等"的语义，Python 不知道新语义下 hash 该怎么算，**宁可让你不可哈希，也不让你违反不变式**（否则 set 里会出现两个"相等"却各占一位的元素）。

正确配套：

```python
def __hash__(self) -> int:
    return hash(self.doc_id)          # 与 __eq__ 用同一批字段
```

### 面试问法："为什么定义了 `__eq__` 之后对象就不能放进 set 了？"

**30 秒答案**："因为 Python 把 `__hash__` 自动设成了 None。哈希表的不变式是'相等对象必须有相同 hash'，一旦你自定义了相等的语义，解释器不知道新语义下 hash 该怎么算，于是宁可让你不可哈希，也不允许出现两个相等却 hash 不同的对象破坏 set/dict。解法是同时定义 `__hash__`，并且用和 `__eq__` 相同的那批字段来算——比如 `hash(self.doc_id)`。"

**追问**：为什么 `hash` 必须和 `eq` 用同一批字段？→ 只比较 doc_id 相等、却用 id(self) 做 hash，两个"相等"的对象 hash 不同，set 里会同时存两份，`in` 判断也会失效。

## 4. `@property`：把方法伪装成属性

```python
@property
def char_count(self) -> int:
    return len(self.content)

d.char_count      # ✅ 无括号，像属性
d.char_count()    # ❌ TypeError: 'int' object is not callable
```

**什么时候用**：值能从其他字段**算出来**时就不存它——存两份必然不同步（D6 缓存脏读的同一个道理：派生数据要么实时算，要么有失效机制）。

**不该用的场景**：需要 IO（查库/发请求）、计算昂贵——属性访问看起来便宜，调用方不会预期它慢。

**进阶**：`@x.setter` 可加写校验；`functools.cached_property` 首次计算后缓存（3.8+，实例级，要求实例有 `__dict__`）。

### 面试问法："@property 和普通属性的区别？"

**30 秒答案**："property 让方法以属性语法访问，好处是可以把'派生值'变成只读计算属性——比如文档字符数是 content 算出来的，不存字段就永远不会不同步；也能在不改调用方代码的前提下加校验或日志。代价是每次访问都会执行函数，所以不适合做 IO 或重计算，否则调用方会以为取属性很便宜而埋下性能坑。"

## 5. 其他值得会用的 dunder

| dunder | 场景 | 注意 |
|---|---|---|
| `__len__` | 容器类 | 必须返回非负 int；`bool()` 会退回到它 |
| `__bool__` | 自定义真值 | 优先于 `__len__` |
| `__getitem__` | 支持 `obj[k]` | 实现后 `for` 也能用（旧协议），但推荐显式实现 `__iter__` |
| `__enter__`/`__exit__` | 上下文管理器 | `__exit__` 返回 True 会吞异常（谨慎） |
| `__call__` | 可调用对象 | 装饰器类/functools.partial 的原理 |
| `__slots__` | 省内存 | 会禁掉 `__dict__`，动态属性失效 |

| 4 | 第四档 #03 漏掉"定义 `__eq__` 未定义 `__hash__`" | 唯一的零症状坑——补课后彻底讲透（§3.2） |

## 7. 30 秒答案集（考前速背）

1. **只写 repr 不写 str** → print 也用 repr。
2. **容器里显示元素** → 用 repr，不用 str。
3. **内容相同的对象 == 为 False** → 没定义 `__eq__`，默认比 id。
4. **NotImplemented 是什么** → 协商失败信号（单例对象，无括号）；之后问对方，都拒绝则退回地址比较。
5. **`__eq__` 后不可哈希** → `__hash__` 被自动置 None；补 `hash(同一批字段)`。
6. **property 适合什么** → 从现有字段推导的派生值；不适合 IO/重计算。
7. **dunder 的本质** → 语法糖的落地接口，实现即获得语法。

## 8. 追问链（面试深挖预演）

| 起点 | 追问 | 你要能答 |
|---|---|---|
| repr/str | 为什么容器用 repr？ | 调试可读、可重建；str 是给终端用户的 |
| `__eq__` | 为什么返回 NotImplemented 而不是 False？ | 给对面机会；子类/其他类型可能认识自己，返回 False 会掐断协商 |
| `__hash__` | hash 冲突会怎样？ | 只影响性能（退化为链表/树），由 `__eq__` 最终判定相等 |
| 可变对象做 key | 为什么危险？ | 哈希值变了但桶位置没变 → 查不到；所以 list/dict 不可哈希 |
| property | 和 cached_property 区别？ | 每次都算 vs 首次算完缓存（实例 `__dict__`） |
| `__slots__` | 什么时候用？ | 大量实例、字段固定时省内存；代价是失去动态属性与多继承灵活性 |
| 协议思想 | 还有哪些协议？ | 迭代、上下文管理、可调用、描述符（property 本身就是描述符）、数值运算 |

5. 定义了 `__eq__` 后把对象放进 set 会怎样？怎么修？
