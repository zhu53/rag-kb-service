## P1 · `read_chunks` 把整个文件读进了内存

```python
with open(path, encoding="utf-8") as f:
    text = f.read()          # ← 10GB 的文件 = 10GB 的内存，在这里炸
for start in range(0, len(text), chunk_size):
    yield text[start : start + chunk_size]
```

**症状：小文件下输出完全正确（smoke 全绿），零症状。** 但这个函数存在的唯一意义就是
"别把整个文件搬进内存"——任务 docstring 里白纸黑字写着禁止 `f.read()` 不带参数。
正确写法是 `while chunk := f.read(chunk_size): yield chunk`（边读边吐）。

**危害等级最高**：测试环境跑得欢，上了生产碰上大日志文件直接 OOM。

## P2 · `Cursor.__iter__` 返回了 self

```python
def __iter__(self) -> "Cursor":
    return self               # ← 第二次 for 时 _pos 已经在末尾
```

第一次 for 正常，**第二次 for 拿到空**——smoke 里只遍历了一次，所以看不出来。
这正是任务里让你实现"返回全新 Cursor"的原因（list 能反复遍历的原理），
你在自己版本里写对了：`return Cursor(self._items)`。

## P3 · 定义了 `__eq__` 没定义 `__hash__`

```python
def __eq__(self, other: object) -> bool: ...
# 没有 __hash__ → Cursor 不可哈希
```

后果：`{cursor: "x"}` 或 `set(cursor_list)` 直接 `TypeError: unhashable type`。
实测确认触发。规则：**定义了 `__eq__` 就把 `__hash__` 置 None（默认行为），
要么自己补一个**（通常 `hash(tuple(self._items))`，与 eq 用同一批字段）。
smoke 里没人往 set 里放，所以零症状——纯读代码题。

## P4 · `paginate` 里 `except Exception` 吞炸弹

```python
try:
    page.append(next(it))
except Exception:             # ← 想接的只是 StopIteration
    break
```

功能上"能跑"（StopIteration 恰好是 Exception 的子类），但上游生成器抛的
**任何**真异常（网络断、解析错、KeyError）都被当成"取完了"静默截断——
**分页悄悄少数据，没有任何报错**。实测：`broken_gen` 里 raise RuntimeError，
分页结果 `[[1]]`，炸弹消失。

规则（D4 刚学的）：只抓你真正想兜底的 → `except StopIteration`。
