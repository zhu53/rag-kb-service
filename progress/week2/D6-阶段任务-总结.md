## 二、关键设计：Cursor 为什么能反复遍历

```python
def __iter__(self) -> "Cursor":
    return Cursor(self._items)    # 新实例，_pos 天然从 0 开始
```

- Cursor **同时是** Iterable（有 `__iter__`）和 Iterator（有 `__next__`）
- 但每次 `for` 都**造一个新的 Cursor**去遍历，原对象 `_pos` 不动 → 可反复遍历
- 这正是 list 的原理：list 自己不数数，每次 `iter(lst)` 新建一个 `list_iterator`
- 对照 D1 的 Countdown：那是一次性光标（`__iter__` 返回 self）；Cursor 是可复用序列——**两者的差别就在 `__iter__` 返回谁**

## 三、首版踩的三个坑（全部自己修复）

| # | 坑 | 症状 | 根因与修法 |
|---|---|---|---|
| 1 | `Cursor = Cursor.__new__()` | UnboundLocalError | **局部变量遮蔽了类名**（右边的 Cursor 找的是未赋值的局部变量）；且造实例就调用类：`return Cursor(self._items)` |
| 2 | `__eq__` 条件装反 | 相同元素判为不等 | 守卫语义是"不是自家人才拒绝"：`if not isinstance(...)` |
| 3 | `__next__` 用 `>` | IndexError（潜伏雷） | `_pos == len` 时也要停：**边界 `>=`**，与 D1 Countdown 的错同族 |

**验收器的一个细节**：第 8 项先测 `__iter__`，坑 3 被 UnboundLocalError 挡住没爆——**修 bug 时要看"还有没有同族雷"，不要只修报错的那一个**。

## 四、验收器设计的两个技巧（以后自建验收器复用）

1. **无限生成器测试**：`paginate(fib(), 4)` 配 `itertools.islice(..., 2)` 只取前两页——既验证"没把无限流 list 进内存"（会卡死=暴露），又不会让测试本身挂死
2. **每项独立 try/except**：一项挂了不连坐，失败信息带类型和实际值，直接指向修复方向

## 六、与项目的串联

```python
# kb-service 真项目里（api/v1/chat.py）：
return StreamingResponse(
    svc.answer_stream(...),           # ← 生成器，被 next 一次吐一小截
    media_type="text/event-stream",
)
```

- `answer_stream` 就是放大版的 `read_chunks`：文件读一块 → LLM 吐一个 token
- 生成器"只能走一遍"在流式里是**特性**：流本来就只有一遍
- `X-Accel-Buffering: no` 防 Nginx 攒缓冲——**生成器吐得再快，中间层攒着也白搭**（Day7/W1 任务 D 答辩过）

## 七、闭卷快问（答案折叠）

<details><summary>1. Cursor 和 Countdown 的本质区别？</summary>__iter__ 返回新实例（可复用）vs 返回 self（一次性光标）。</details>
<details><summary>2. paginate 为什么不能用 list(items)？</summary>items 可能是无限生成器，list 会永远跑下去卡死；必须用 next 逐个取、攒满一页就 yield。</details>
<details><summary>3. f.read(n) 怎么判断读完了？</summary>返回空字符串 ""，这是 while 循环的退出条件。</details>
<details><summary>4. except Exception: 在 paginate 里为什么危险？</summary>StopIteration 恰好是 Exception 子类所以"能跑"，但上游任何真异常也被当"取完了"→ 静默少数据；只该写 except StopIteration。</details>
<details><summary>5. 自己的 Cursor 缺什么？什么时候要补？</summary>__hash__（定义了 __eq__ 自动被置 None）；需要进 set / 当 dict key 时补 hash(tuple(self._items))。</details>
