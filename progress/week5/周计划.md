# W5 周计划 · 类型注解与质量门禁（S1 第 4 周 / 收官）

> 路线图原定范围：`typing`（`Optional`/`Union`/`Literal`/`Protocol`/`TypeVar`/`Generic`/`TypedDict`）、`mypy --strict` 落地、`ruff` + `pre-commit`。
> 原定验收：「mypy strict 0 error，ruff 0 warning，pre-commit 生效」。
> **验收上调**：0 error 只是及格线。本周主菜是**"门禁拦得住错误"**——不是把错误改没，而是下次写错时它必须红。见「验收清单」最后两条。

## 本周主线问题

> **"类型检查怎么才能拦住真错误，而不是变成一堆 `noqa` 和 `cast`？"**
>
> 上一周证明了"测试能不能抓住 bug"要靠变异测试来验。这一周同理：**一个 0 error 的 mypy 报告，可能是因为代码真的对，也可能是因为你到处写了 `Any`。**
> 所以本周的验收方式不是"看报错数"，而是**故意写错，看它红不红**。

## 第四档安排（本周主题适配）

- **#12 类型的坑**：一份 `mypy --strict` 零错误的代码，里面埋了
  ① `Protocol` 变异性写反（静默匹配不上，报错信息极难懂）
  ② `TypedDict(total=False)` 当必填用
  ③ `overload` 顺序错导致永远走不到精确分支
  ④ `cast` 把一个 `Optional` 硬说成非空
- **#13 门禁被绕过的坑**：一份"检查全绿"的项目，找出
  ① 过宽的 `per-file-ignores` 把整个 `tests/` 的规则关了
  ② `# noqa: E501` 挂在错误的行上（放过了真正的问题）
  ③ `overrides` 里 `ignore_missing_imports` 覆盖了整个包，导致类型全变 `Any`
  ④ CI 只跑 `ruff` 不跑 `mypy`，本地却以为"门禁过了"

## 教学约定（沿用）

- 每个讲到的知识点都要**弄懂弄全**，不数概念个数；不重要/枝节可精简
- 教材按**零基础版**写：痛点 → 最小可跑示例 → 逐层展开 → 机制 → 易错表 → 实验 → 面试问法 → 闭卷自测

- 第四档每次验收必有，3–4 个坑，至少 1 个运行时零症状
- **命令一律双平台并列**（PowerShell + bash），不给单平台写法
- 技术断言先实测，用 `kb-service/.venv` 的 Python 3.11
- `git push` 由用户自己执行，AI 只给命令块
