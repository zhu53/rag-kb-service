## 三、30 秒答案集（W5 版）

**Q: mypy 全绿代表没类型 bug 吗？**
不代表。mypy 保证声明层自洽：实参对形参、return 对返回类型、每个操作被声明类型支持（属性访问是最大检查面，错误码 `attr-defined`/`union-attr`）。它对 `cast`/`Any`/`type: ignore` 一律放行——检查器没法阻止你关掉它自己。证明它有效只能靠注入错误实测。

**Q: Protocol 和 ABC 怎么选？**
Protocol 是结构化类型：只比较形状，不要求 import/继承，契约由消费方定义，测试 fake 零耦合。ABC 是名义继承：必须显式继承，但**额外**支持运行时 isinstance（Protocol 默认不能，`@runtime_checkable` 也只查成员存在）。选型判据：依赖方向想倒转、或实现方不该知道契约存在 → Protocol；需要运行时类型判断的类层次 → ABC。

**Q: 参数逆变、返回协变，为什么？**
实现方是承担风险的一方：参数必须接受得**不窄于**协议（否则协议承诺的输入会炸实现），返回值必须**不宽于**协议（否则调用方拿到处理不了的类型）。写反了 mypy 报 `arg-type`/`return-value`，但**运行时零检查**——压掉报错就是埋雷，错误从编译期可拦截退化成线上偶发故障。`list` 因为可写所以不变，`Sequence` 只读所以协变。

**Q: 三种收窄 Any 的手段怎么选？**
先问 Any 的**来源**。库给的（如无 stub 的 `jwt.encode`）→ `cast`，零运行时开销，前提是你比 mypy 多知道文档承诺；数据来的 → `assert isinstance` 或边界处 `model_validate`，因为你对数据一无所知；长期治本 → 改设计（建模型/TypedDict 让 Any 不再产生）。数据用 cast 是最危险的：错误延迟到远处才炸。

**Q: TypedDict 和 pydantic 模型怎么选？**
判据是"要不要运行时信任"。内部数据（DB 行、store 里的 dict）→ TypedDict，零运行时开销、纯静态形状；外部数据（HTTP、第三方 API）→ pydantic，运行时校验 + 类型转换 + 带字段路径的报错。TypedDict 还有个坑：名义式——形状兼容的两个 TypedDict 也不能互相赋值。

**Q: overload 运行时发生了什么？**
`@overload` 变体只给 mypy 看，运行时被最后一个同名定义覆盖，真正执行的只有实现体。三个必要条件：≥2 个变体 + 1 个不加装饰器的实现体 + 实现体签名兼容所有变体。顺序错（宽的在前）精确分支永不可达——mypy 自己会报 `overload-cannot-match`。

**Q: 幂等键和缓存是一回事吗？（日课加餐）**
不是。缓存为**性能**而生：key 是查询，丢了重算。幂等键为**正确性**而生：客户端为业务操作生成唯一 ID + 服务端唯一索引，丢了会重复扣款。判别一句话：一个丢了能重来，一个丢了会出错。

## 六、可讲的故事（面试素材，按杀伤力排）

**故事 1：一次 500 的降级修复（边界校验）**
"我给项目加类型门禁时实测发现：JWT 签名合法但 `sub` 不是 UUID 时，接口返回 500 而不是 401。根因是载荷用 `dict[str, Any]` 承载，`Any` 让所有校验失效。修复分三层：载荷换成 pydantic 模型 `TokenClaims`（`sub: str` 必填、`exp: int`——JWT 的 NumericDate 本来就是 int）、`ValidationError` 和 `UUID` 的 `ValueError` 统一翻译成 `UnauthorizedError`、补缺 sub 和非 UUID 两条测试。`security.py` 覆盖率从 88% 到 94%。这件事让我把'类型安全'和'值安全'分开：mypy 管前者，边界校验管后者。"

**故事 2：注入 5 类错误，2 类全绿（反脆弱）**
"我信不过'配置了就是有效的'，所以往自己代码里注入了 5 类人类常犯的类型错误。漏写返回注解、参数类型写错、多余 ignore——3 类门禁全红；但把必填字段降级成 `Any`、删掉 `from __future__`——2 类全绿。结论：mypy 无法阻止你关掉它自己，这类盲区只能靠 review 和登记制度补。这个故事我总在回答'你怎么保证 AI 生成的代码没问题'时讲——先假设它有问题，再让门禁证明。"

**故事 3：一本 Any 的账（25 → 2）**
"我把项目里 `dict[str, Any]` 从 25 处清到 2 处，剩下两处每处都有登记：`logging.py` 的日志载荷天然异构（**有意保留**，删除条件：无）；`kb_repo.py` 一处 cast 绕开 TypedDict.update 的窄参数（删除条件：重构为逐字段赋值）。第三处 `config.py` 的 `type: ignore` 是 pydantic 插件生效后被 `unused-ignore` 自动逼死的——这说明删除条件不是理论，工具链会真的执法。"
