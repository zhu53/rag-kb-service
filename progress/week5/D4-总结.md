## 二、逐个知识点讲透

### 1. 边界校验：`model_validate` 与 `cast` 的分工

**一句话定义**：边界校验是在"外部数据进入类型系统"的那一行做一次结构与类型检查，之后内部代码只信任类型、不再防御。

**为什么存在**：没有它，第三方 API 返回的任意 JSON 会以 `Any` 的形态一路流进业务层——`resp.json()` 就是 `Any` 的入口。`Any` 会传染：`data["choices"][0]["message"]["content"]` 这一串下标每一步都是 `Any`，mypy 全程放行。等错误暴露时，往往已经离入口几十行远，栈里看不到真正的问题点。反过来，在入口加一行 `model_validate`，错误就在那一行变成 `LLMResponseError`，位置和原因都对得上。

**怎么用**：

```python
# src/kb_service/services/llm_client.py
class _Message(BaseModel):
    content: str


class _Choice(BaseModel):
    message: _Message


class _ChatCompletion(BaseModel):
    choices: list[_Choice]


data = resp.json()          # Any —— 边界在这里
try:
    parsed = _ChatCompletion.model_validate(data)
except ValidationError as exc:
    raise LLMResponseError("LLM 响应结构不符合预期") from exc
if not parsed.choices:
    raise LLMResponseError("LLM 响应 choices 为空")
return parsed.choices[0].message.content
```

**底层机制**：pydantic v2 把模型编译成 **validator 函数树**（`pydantic-core`，Rust 实现），`model_validate` 时逐个字段按 schema 走：类型不对 → 记一条 error（含 `loc` 路径、`type`、`input`），全部走完再统一抛 `ValidationError`。所以错误是**收集式**的，一次能报多个字段。默认 `extra="ignore"`（多余键静默丢弃）、lax 模式——但 lax **也不做** `int → str` 隐式转换，实测 `{"content": 123}` 报 `string_type`，这正是我们那条新测试的断言。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 用 `cast(str, data["content"])` 代替校验 | `content=123` 静默通过，下游 f-string 才炸 | 边界只用 `model_validate`（或手写 `isinstance` 校验） |
| 2 | 校验完还用字典方式取值 | `parsed["choices"]` → `TypeError: not subscriptable` | `parsed.choices`（属性访问） |
| 3 | 捕获 `ValidationError` 后 `return ""` | 错误伪装成"模型答了个空"，监控看不到 | 抛领域异常，让上层决定降级 |
| 4 | 校验放在 service 深处 | 每层都要防御，且同一段数据校验多次 | 校验贴着"进入系统的那一行"（repo / client） |
| 5 | 忘了 `from exc` | 原始 `ValidationError` 的栈断掉，只剩"结构不符合预期" | `raise X(...) from exc` |

**面试问法**：「第三方 API 返回的 JSON 结构不可信，你代码里怎么处理？」

> **30 秒版**：在客户端那一层用 pydantic 模型挡住——`model_validate(resp.json())`，校验失败抛我们自己的 `LLMResponseError`。这样 Any 只存在于 `resp.json()` 那一行，出了这一行全部是有类型的对象，错误也在同一行被翻译成领域异常。

**追问链**：

→ *"pydantic 怎么知道字段不对？ValidationError 里有什么？"*
它把模型编译成 Rust 的 validator，逐字段比对 schema，收集 `loc`/`type`/`input` 三元组，最后统一抛。`.errors()` 能拿到每条的具体路径，日志里打这个比打整段字符串有用。

→ *"字段多了、少了、类型错分别什么行为？"*
少了必填字段 → `missing`；类型错 → `string_type` 等；多了默认**静默忽略**（`extra="ignore"`）。想拒收多余字段要显式 `model_config = ConfigDict(extra="forbid")`——对外部 API 我倾向 `ignore`（供应商加字段不该让我的服务挂），对内部请求体倾向 `forbid`（多余字段说明调用方搞错了）。

→ *"LLM 输出要结构化 JSON，你怎么保证它一定合法？"*
三层：① 用 function calling / `response_format={"type": "json_object"}` 让模型按 schema 吐；② 拿到后 `model_validate`，失败进重试（把校验错误回喂给模型）；③ 重试 N 次仍失败就走降级（返回兜底文案 + 告警）。**只有第 ② 层是硬保证，第 ① 层是降低失败率，第 ③ 层是兜底**——生产上三层都要。

### 2. 异常翻译：把库异常翻成领域异常，再翻成 HTTP 码

**一句话定义**：每一层只用自己的语言抛异常，跨层由最外层 HTTP handler 统一翻译成状态码。

**为什么存在**：这次抓到的真 bug 就是反例。`deps.py` 里 `UUID(str(sub))` 遇到非 UUID 抛 `ValueError`，没人接住 → 冒到 FastAPI 顶层 → **500**。可这明明是"客户端给了一个坏 token"，应该是 **401**。500 的含义是"服务端错了"，会触发告警、拉高错误率、让 SRE 半夜爬起来查一个根本不存在的服务端故障。

**怎么用**：

```python
# api/deps.py
try:
    user_id = UUID(str(sub))
except ValueError as exc:          # 库异常（标准库）
    raise UnauthorizedError("凭证载荷不合法") from exc   # → 领域异常


# core/security.py
try:
    raw = jwt.decode(token, settings.secret_key, algorithms=[settings.algorithm])
except JWTError as exc:            # 库异常（python-jose）
    raise UnauthorizedError("凭证无效或已过期") from exc

try:
    return TokenClaims.model_validate(raw)
except ValidationError as exc:     # 库异常（pydantic）
    raise UnauthorizedError("凭证载荷不合法") from exc
```

**底层机制**：FastAPI 维护一张 `exception_handlers` 注册表（异常类 → 处理函数），`HTTPException` 与自定义异常各有一条。**没被任何 handler 命中的异常**会走 Starlette 的默认 `ServerErrorMiddleware`：返回 500、只在日志里留 traceback、响应体不带细节。所以"翻译"的实质是**让异常落进某条 handler**，而不是让 traceback 好看。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 只捕 `JWTError`，忘了载荷结构错 | 签名对但缺 `sub` → `ValidationError` 冒出去 → 500 | 解码和校验是**两段** try，各捕各的 |
| 2 | `except Exception` 兜底成 401 | 数据库炸了也返回"凭证无效"，真故障被掩盖 | 只捕**能确定是客户端问题**的异常类型 |
| 3 | 401 和 403 混用 | 前端按 401 跳登录，其实是无权限 | 401 = 没认证 / 凭证无效；403 = 认证了但没权限 |
| 4 | `raise X(...)` 不带 `from exc` | 原始栈丢掉，排查时只剩一句人话 | `from exc` 保留 cause 链 |
| 5 | 把 DB 连接失败也翻成 4xx | 客户端疯狂重试，永远好不了 | 5xx 才该重试，4xx 重试无意义 |

**面试问法**：「接口返回 500 和 400 的边界你怎么划？」

> **30 秒版**：4xx 是"客户端能改的错"——参数格式、凭证、权限、资源不存在；5xx 是"客户端改不了、重试可能有用"的错——依赖挂了、数据库连不上、代码 bug。JWT 载荷里 `sub` 不是 UUID 属于前者，所以必须是 401 而不是 500。

**追问链**：

→ *"没被捕获的异常最后去哪了？"*
进 Starlette 的 `ServerErrorMiddleware`，返回 500 + 空体，traceback 只进日志。所以"没翻译"不等于"没记录"，但**客户端拿不到任何有用信息**，而且会污染服务端错误率指标。

→ *"哪些异常绝对不能翻成 4xx？"*
所有"重试可能成功"的：数据库连接超时、下游 5xx、线程池满。翻成 4xx 会让客户端放弃重试；翻成 5xx 才有重试/熔断的意义。

→ *"LLM 调用超时了，你返回什么？"*
5xx（通常 503/504），并触发降级：返回缓存答案或兜底文案，同时上报。**不能翻成 400**——用户没问题，是我们的依赖有问题。这里还涉及超时预算：整个请求 3 秒，LLM 只给 1.5 秒，超了就降级，而不是干等。

### 3. `cast` 的两种用途

**一句话定义**：`cast(T, x)` 是纯静态声明——告诉类型检查器"把 `x` 当成 `T`"，运行时**一行代码都不做**。

**为什么存在**：有些地方类型检查器确实推不出来：库没有注解（返回值是 `Any`）、或者你刚做完手工校验（检查器看不见你的 `if`）。没有 `cast`，这类地方只能写 `# type: ignore`——而 `# type: ignore` 连"我认为它是什么"都没说，信息量更低。

**怎么用**：关键区别在**缺口来自哪里**。

```python
# ✅ 好 cast：收敛"库的类型缺口"
# jose 没有注解，jwt.encode 在 mypy 眼里返回 Any；strict 的 no-any-return
# 不允许把 Any 直接 return 出去。这里 cast 的是库的返回值，行为由库的文档保证。
token = jwt.encode(payload, settings.secret_key, algorithm=settings.algorithm)
return cast(str, token)


# ❌ 坏 cast：掩盖"数据的校验缺口"
# value 是外部传进来的未知值，cast 之后 None 照样往下流
# （第四档 #14 坑 1 就是这个）
return cast(str, row.get("name"))
```

**底层机制**：`typing.cast` 的实现就是 `def cast(typ, val): return val` —— 一个恒等函数，运行时开销是一次函数调用（CPython 3.11 之后甚至被特化优化）。它真正的作用对象是 mypy/pyright 的类型推导：把表达式类型替换为 `typ`，**不生成任何检查**。所以 cast 写错了不会有任何运行时症状，这是它最危险的地方。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 拿 `cast` 消掉 error | 错误只是换个地方炸，且栈里看不到 cast 那行 | 先问"这个值凭什么一定是 T"，答不上就别 cast |
| 2 | `cast(str, x)` 但 `x` 是 `None` | `f"{None:<16}"` → `TypeError: unsupported format string passed to NoneType.__format__`（实测） | 边界处用 `model_validate` / `assert isinstance` |
| 3 | cast 之后没有注释 | 半年后没人知道它依赖什么前提，不敢删也不敢改 | 注释写清"依赖哪个库的哪条承诺" |
| 4 | 用 `# type: ignore` 代替 | 连"我保证是什么"都没说，改坏了也看不出来 | 优先 cast（有类型信息），其次 ignore 带 error code |
| 5 | 在边界用 cast 当校验 | 全部字段"看起来"有类型，其实一个都没验 | 边界只做 `model_validate`，cast 只用于库缺口 |

**面试问法**：「`cast` 和 `assert isinstance` 怎么选？」

> **30 秒版**：`cast` 是零成本纯声明，运行时什么都不做，只适合"我确定类型、只是检查器看不见"的地方，比如无类型库的返回值；`assert isinstance` 有真实运行时检查，失败会立刻抛，适合"我需要真的验一下、并且希望它当场炸"的地方。判据是：**错了你希望什么时候知道**——编译期/静态检查就够用 cast，必须运行时兜底用 assert。

**追问链**：

→ *"cast 有运行时开销吗？"*
实质上没有。`typing.cast` 是 `return val` 的恒等函数，CPython 3.11+ 还会做特化。所以性能不是选择依据，**"错了什么时候暴露"才是**。

→ *"什么时候 assert 比 cast 好？"*
当"类型错了应该立刻失败"时。比如从配置读出一个值、要当端口号用：`assert isinstance(port, int)` 会在启动时炸；`cast(int, ...)` 会等到 bind 的时候炸在别处。另一个判据：assert 可以被 `-O` 去掉，所以不能用在有副作用的校验上。

→ *"一个无类型的 SDK 要接进来，这些 cast 你怎么管？"*
不让它们散落在业务代码里——写一层 wrapper（`VendorClient`），所有 `cast` 集中在 wrapper 内部，并且每个都配一条边界测试（畸形响应必须抛领域异常）。业务层只看到 wrapper 的强类型接口，SDK 换版本时只改一个文件。

### 4. 第三方库的类型三状态

**一句话定义**：一个库对 mypy 的可见性只有三种——自带 `py.typed`（完整签名）、有外部 stub 包（`types-*`）、完全没有（整个模块是 `Any`）。

**为什么存在**：不知道自己在哪一状态，就会做错两件事：给有类型的库写多余 override（把真实签名挡掉），或者以为"类型检查过了"而其实整条链路都是 `Any`。今天这两件事都发生了——override 方向做反，把该放行的 `jose` 拦了、把不需要的 `passlib` 放行了。

**怎么用**：

```powershell
# Windows PowerShell —— 一次看清装了哪些 stub 包
& .\.venv\Scripts\python.exe -m pip list | Select-String "types-"
```

```bash
# Git Bash / Linux / macOS
./.venv/Scripts/python.exe -m pip list | grep "types-"
```

判据表：

| 状态 | 怎么认 | mypy 报什么（strict） | 要不要 override |
|---|---|---|---|
| 自带 `py.typed` | 包目录下有 `py.typed` 文件 | 不报 | **不要** |
| 有 `types-X` stub | `pip list` 里有 `types-X` | 不报 | **不要** |
| 全无 | 两者都没有 | `import-untyped` | **要**（精确到包） |

**底层机制**：PEP 561 定义了三种分发方式。① **内联**：包作者在 wheel 里放 `py.typed` marker，mypy 直接读包内的 `.py`/`.pyi`；② **stub-only**：单独发布 `types-X`，安装后在 `site-packages/X-stubs/` 下，mypy 按 "`X-stubs` 目录优先于 `X` 的源码" 的规则查找；③ 都没有时，mypy 把整个模块当 `Any`，并且**在 strict 下报 `import-untyped`**（注意：不是 `import-not-found`——后者意思是"连包都找不到"）。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 装了 `types-X` 还写 override | 真实签名被挡成 Any，库用法写错也不报 | `pip list` 先查，有 stub 就删 override |
| 2 | 删错方向（把无 stub 的库从 override 里删了） | `security.py:6: Library stubs not installed for "jose" [import-untyped]` | override 里只留"确实没有类型信息"的库 |
| 3 | 以为 stub 一定准确 | stub 可能落后于库版本，签名对不上 | 用 `stubtest` 对比 stub 与运行时 |
| 4 | 自己 `--strict` 跑与项目配置结果不同 | 一时报 `import-untyped`、一时 Success | 先确认是否装了 `types-*`（`--strict` 只是把默认值拉满） |
| 5 | 把"库没类型"当成"不用管" | 整条链路静默变 Any，类型检查形同虚设 | 无类型的库一律包 wrapper + 边界测试 |

**面试问法**：「引入一个没有类型标注的第三方库，你怎么办？」

> **30 秒版**：先看它有没有 `py.typed` 或现成的 `types-*` 包，有就直接用。都没有的话，我把它包一层自己的 wrapper，所有 `cast` 和默认值处理集中在 wrapper 里，业务层只依赖 wrapper 的强类型接口；同时给边界补畸形输入的测试，因为类型检查器在这条链路上帮不了我。

**追问链**：

→ *"`py.typed` 是什么？PEP 561 解决什么问题？"*
PEP 561 之前，mypy 不知道该不该信一个包里的注解——有的包注解是给文档用的、早就过期了。`py.typed` 是一个空 marker 文件，作者放进去就等于承诺"我的注解是维护的、可以信"。stub-only 包则用 `X-stubs` 目录约定。

→ *"stub 和库源码不一致怎么办？"*
用 `stubtest`：它对比 stub 声明的签名与运行时对象的真实签名，报出缺失/多余/类型不符。CI 里对自研 stub 跑这个，能挡住"库升级了但 stub 没跟"。

→ *"团队要不要给无类型 SDK 自己写 stub？"*
看调用面。如果只有 3–5 个函数、且都在一个 wrapper 里，`cast` + 测试更划算；如果一个 SDK 被 20 个文件调用，写 `.pyi` 值得——一次性成本换全局类型安全，而且写 stub 的过程本身会暴露你对这个 API 的误解。

### 5. `ignore_missing_imports` 的粒度

**一句话定义**：mypy 的配置开关，决定"找不到类型信息"时是报错还是当 `Any`；关键是它有两种粒度——全局和按模块。

**为什么存在**：无类型库太多，全报错就没法用。但**全局打开**会把另一种错误一起吞掉：包名拼错。今天实测：全局开 `ignore_missing_imports = true` 后写 `import httpxx`（多一个 x），mypy 静默 `Success`，代码跑到运行时才 `ModuleNotFoundError`。

**怎么用**：

```toml
# kb-service/pyproject.toml
[tool.mypy]
strict = true
# 不写 ignore_missing_imports —— 全局开关一律不开

[[tool.mypy.overrides]]
module = ["jose.*"]          # 精确到包，且带 .* 覆盖子模块
ignore_missing_imports = true
```

**底层机制**：mypy 的 import 解析顺序是——先找本地 stub（`X.pyi`）→ 找 `X-stubs` 包 → 找 `X` 包内的 `py.typed` → 都没有则产生 `import-untyped`（包存在但无类型）或 `import-not-found`（包不存在）。这两个是**不同的 error code**，而 `ignore_missing_imports` 只抑制前者。`[[tool.mypy.overrides]]` 是一张"模块路径前缀 → 配置覆盖"的规则表，按顺序匹配，**后面的覆盖前面的**；`module = ["jose"]` 不匹配 `jose.jwt`，所以必须写 `jose.*`。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 全局 `ignore_missing_imports = true` | `import httpxx` 拼错也通过，运行时才炸 | 用 `[[tool.mypy.overrides]]` 精确到包 |
| 2 | `module = ["jose"]` 少写 `.*` | 子模块 `jose.jwt` 仍然报 `import-untyped` | 一律写 `包名.*` |
| 3 | override 命中本来有类型的库 | 签名退化成 Any，库用错也不报 | 先查 `py.typed` / `types-*` |
| 4 | 用 `disable_error_code = ["import-untyped"]` 图省事 | 等于全局关掉这一类，等价于坑 1 | 同上，按模块开 |
| 5 | 只在本地 pyproject 配置，CI 用 `--strict` 覆盖 | 本地绿、CI 红（或反过来） | CI 用同一份配置，不要额外命令行开关 |

**面试问法**：「怎么保证"某个库没类型"不会变成"整条链路没类型"？」

> **30 秒版**：不全局关类型检查，而是按模块精确放行——`overrides` 里只列确实没有 stub 的包。然后在这些库的调用处收敛：包一层 wrapper，`cast` 集中在里面，业务层拿到的都是强类型。再用测试兜住边界，因为静态检查在这条链路上是空的。

**追问链**：

→ *"`import-untyped` 和 `import-not-found` 的区别？"*
前者是"包找了但没类型信息"（装了个没 `py.typed`、也没 `types-*` 的库），后者是"压根没这个包"。**前者可以放行，后者必须报**——后者九成是拼错了或忘了装依赖。

→ *"per-module override 能覆盖哪些选项？"*
基本所有 mypy 选项都能按模块覆盖：`disallow_untyped_defs`、`disallow_any_expr`、`warn_return_any` 等。常见用法是给 legacy 目录单独放宽，新代码保持 strict——迁移期很实用。

→ *"引入无类型 SDK 的完整落地流程？"*
① 确认无 stub → ② 写 wrapper（强类型接口 + 集中 cast） → ③ 在 `overrides` 里只放行这个包 → ④ 给 wrapper 补边界测试（畸形响应、超时、空值） → ⑤ 在 wrapper 的 docstring 里写清"依赖 SDK 哪个版本的哪个行为"，升级时复验。

### 6. 契约变更的连带成本

**一句话定义**：改一个函数的返回类型，等于同时改掉所有调用点对它的假设——签名是契约，不是注释。

**为什么存在**：今天最典型的漏点。`decode_access_token` 从 `dict[str, Any]` 改成 `TokenClaims`，`deps.py` 里一处改了，但**测试里有 3 处 `payload["sub"]` 没改**。静态检查报了 3 个 `[index]`，pytest 挂了 3 个 `TypeError` —— 它们指的是同一件事，分别来自两个不同的报警器。

**怎么用**：改完签名**立刻**跑两条命令，缺一不可。

```powershell
# Windows PowerShell —— 静态找调用点
cd kb-service
& .\.venv\Scripts\python.exe -m mypy src tests
& .\.venv\Scripts\python.exe scripts\check.py
```

```bash
# Git Bash / Linux / macOS
cd kb-service
./.venv/Scripts/python.exe -m mypy src tests
./.venv/Scripts/python.exe scripts/check.py
```

**底层机制**：mypy 做全局名字解析 + 类型推导，改签名会让所有引用点重新检查——所以它**能找出你没运行过的调用点**。而运行时的 `payload["sub"]` 走的是 `__getitem__` 协议，pydantic 的 `BaseModel` 根本没实现它，于是 `TypeError: 'TokenClaims' object is not subscriptable`。两者的分工：mypy 找"类型上不可能"的地方（包括死代码里的调用），pytest 找"类型上可能但逻辑变了"的地方。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 只改 `src/` 不改 `tests/` | 3 个测试 `TypeError`，且 `mypy` 报 `[index]` | 改签名后全仓跑 mypy，别只跑 src |
| 2 | 只跑 pytest 不看 mypy | 没被测试覆盖的调用点漏掉 | 两者都跑：静态找全量，动态验行为 |
| 3 | 加个 dict-like 兼容层 | 迁移"看起来"平滑，实际两套用法长期共存 | 一次性改完，别留兼容层 |
| 4 | 一次改多个签名 | 一堆失败分不清是哪个改动引起的 | 一次一个签名，改完立刻跑门禁 |
| 5 | 忘了改文档/docstring 里的示例 | 文档与代码不一致，下一个人照抄就错 | 签名和 docstring 同一次提交改完 |

**面试问法**：「你怎么保证重构不破坏调用方？」

> **30 秒版**：靠两道网——静态类型检查和测试。改签名后 mypy 会把所有不兼容的调用点标出来，包括测试和死代码里的；pytest 验证行为没变。这次把返回值从 dict 换成模型，mypy 报了 3 个下标错误、pytest 挂了 3 个测试，指的都是测试里那 3 处没跟着改的调用。

**追问链**：

→ *"静态检查和测试分别能发现什么、漏什么？"*
mypy 能覆盖**所有**引用点（包括没有测试的路径），但看不见"逻辑变了但类型没变"；pytest 能验证行为，但只覆盖被测到的路径。所以缺一不可——这也是为什么我不接受"测试通过就行"。

→ *"公共 API 要渐进迁移怎么办？"*
加新函数、旧函数内部转调新函数并标 `@deprecated`（或 docstring 标注），给一个版本的过渡期，期间两套都能用；到版本边界删旧的。**绝不要**让旧函数返回"半个新类型"的兼容对象，那会把迁移成本转嫁给每一个调用方。

→ *"多人协作时怎么防止别人改坏你的契约？"*
CI 门禁（mypy + 测试必过才能合）是第一层；第二层是 CODEOWNERS/评审，动到接口文件必须相关人 review；第三层是接口的契约测试——对 `TokenClaims` 这种载荷模型，直接断言"缺 `sub` 必须 401"，谁改坏了测试立刻红。

### 7. JWT 载荷的类型不对称

**一句话定义**：同一份 payload，签发方向能塞 `datetime`，解码方向拿回来的是 `int`（Unix 秒）——两个方向不能共用一套类型。

**为什么存在**：RFC 7519 规定 `exp`/`iat` 是 **NumericDate**（数字），不是 ISO 字符串、也不是结构化时间。python-jose 在 `encode` 时把 `datetime` 转成时间戳，但 `decode` 时**不会转回来**。如果不显式建模这一点，你会写下 `exp: datetime` 的模型，然后在比较时间时拿到 `int` 与 `datetime` 相减 → `TypeError`。

**怎么用**：

```python
class TokenClaims(BaseModel):
    """JWT 载荷的业务契约（decode 之后的方向）。

    注意 exp/iat 在 decode 后是 Unix 秒（int），不是 datetime ——
    编码方向塞 datetime，解码方向拿回来 int，两个方向不能共用一套类型。
    """

    sub: str
    iat: int | None = None
    exp: int | None = None
```

**底层机制**：`jwt.encode` 内部走 `json.dumps(payload, default=...)`，`datetime` 由 jose 自己的 default encoder 转成 `int(dt.timestamp())`；`jwt.decode` 做三件事——验签、验 `exp`/`nbf`（用当前时间戳比数字）、`json.loads` 返回 dict。**没有任何一步把数字还原成 datetime**，因为 JSON 里没有时间类型。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 模型里写 `exp: datetime` | 运行时值是 `int`，与 datetime 相减/比较 `TypeError` | 解码方向一律 `int`（或显式 `field_validator` 转换） |
| 2 | 以为 `exp` 是毫秒 | 时间差 1000 倍，token 立刻"过期"或永不过期 | NumericDate 是**秒** |
| 3 | 用 `datetime.utcnow()`（naive） | 与 aware 时间比较报错；且 Windows 上 3.11 精度只有 15.6ms | 统一 `datetime.now(UTC)` |
| 4 | 断言 `payload == 原 dict` | 时间字段永不相等（datetime vs int） | 只断言关心的字段 |
| 5 | 忘了 `exp` 可选 | 缺 `exp` 的 token 被判为不合法（或永不过期，取决于实现） | 按业务定：`int \| None` + 单独校验策略 |

**面试问法**：「JWT 里的 `exp` 是什么类型？为什么不是字符串？」

> **30 秒版**：`exp` 是 NumericDate，也就是 Unix 秒的数字。JWT 要跨语言、跨时区传递，数字是唯一没有歧义的表示；字符串要靠格式约定，各语言解析器容易不一致。所以签发时我把 `datetime` 交进去，jose 帮我转成秒，解码回来就是 `int`。

**追问链**：

→ *"为什么用数字而不是 ISO 8601 字符串？"*
RFC 7519 要的是一个所有语言都能无歧义比较的值。数字比较不需要解析器、不受时区影响、也不受格式（带不带 Z、带不带毫秒）影响。代价是可读性差——排查时得手动转。

→ *"服务器之间时钟不同步怎么办？"*
jose 支持 `leeway` 参数，允许一定秒数的偏移（比如 30 秒）。但 leeway 只解决边界抖动，解决不了大偏差；生产上所有机器必须走 NTP。**另一个常见坑**：签发和校验用了不同机器的时钟，宁可给 5 分钟 leeway 也别让用户莫名 401。

→ *"token 怎么撤销？"*
JWT 本身无状态、签出去就收不回。两个方案：① 短 TTL（15 分钟）+ refresh token，把撤销窗口压到可接受；② 维护黑名单（Redis，key 是 `jti`，TTL 设为 token 剩余有效期）——一旦上黑名单，每次请求都要查 Redis，就退化成"半个有状态鉴权"了。我们项目现在是最简版，只有 ① 的前半段。

### 8. 覆盖率是"执行证据"不是"质量指标"

**一句话定义**：行覆盖率只回答"这行代码有没有被执行过"，不回答"这段代码对不对"。

**为什么存在**：今天 `security.py` 覆盖率 88%，`Missing` 列写着 `64-65` —— 正是新加的 `except ValidationError → UnauthorizedError` 那两行。意思是：**这段错误处理代码一次都没跑过**，它是对是错完全未知。补了 `test_missing_sub_returns_401` 之后覆盖率变 94%，那两行从 Missing 里消失——这才是覆盖率真正的用法：**当"未验证代码"的探测器**。

**怎么用**：

```powershell
# Windows PowerShell —— 只看未覆盖行
cd kb-service
& .\.venv\Scripts\python.exe -m pytest --cov=src/kb_service --cov-report=term-missing -q
```

```bash
# Git Bash / Linux / macOS
cd kb-service
./.venv/Scripts/python.exe -m pytest --cov=src/kb_service --cov-report=term-missing -q
```

**底层机制**：coverage.py 用 `sys.settrace`（3.12 起可用 `sys.monitoring`）在每行执行时打点，记录 (文件, 行号) 集合；`branch = true` 时还记录**跳转边**（所以报告里会出现 `41->exit`、`57->exit` 这种"这个分支从未被走到"）。它不分析代码语义，所以"执行过"和"对"完全是两件事——一行 `assert True` 也能把覆盖率刷上去。

**易错点**：

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | 追 100% | 写一堆无断言的测试，指标好看、bug 照样 | 定 90–95% 的门槛，剩余部分逐个说明理由 |
| 2 | 只看总数不看 `Missing` | 关键错误分支从没跑过，总数依然 96% | 按文件看 `Missing` 列，重点盯 `except` 分支 |
| 3 | 用 `# pragma: no cover` 掩盖 | 未测代码被合法化，越积越多 | 只对"确实无法测试"的（如 `if TYPE_CHECKING`）用 |
| 4 | 把覆盖率当"没 bug 证明" | 线上照样炸 | 覆盖率 + 变异测试 + 边界用例三者配合 |
| 5 | 覆盖率掉了就慌 | 重构删代码也会让分母变，覆盖率反而升 | 关注"新增代码有没有被测"（diff coverage） |

**面试问法**：「你们项目覆盖率多少？」

> **30 秒版**：门禁卡 95%，现在 96.5%。但我更看 `Missing` 列——比如有次发现新写的 `except ValidationError` 分支覆盖率是 88% 里缺的那部分，等于这段错误处理从没被执行过，我补了一条"载荷缺 sub 必须 401"的测试把它盖住。覆盖率对我来说是**找未验证代码**的工具，不是 KPI。

**追问链**：

→ *"行覆盖和分支覆盖的区别？"*
行覆盖只看"这行有没有执行"，分支覆盖还看"每个判断的两条边有没有都走过"。`if x: a(); else: b()` 只测 x 为真时，行覆盖可能 100%（如果 else 那行也被别的用例走过），但分支覆盖会指出 `else` 那条边没走。

→ *"覆盖率 100% 还会漏什么？"*
漏"没写出来的代码"和"逻辑错但都被执行了"。比如 `if not parsed.choices` 这个判断，覆盖率能证明它被执行过，但证明不了判断条件写对了——那要靠变异测试：把 `not` 删掉，看测试会不会红。

→ *"AI 生成的代码你怎么验？"*
先写测试再让它生成（测试是我对需求的理解），然后看生成的代码跑不跑得过；之后做两件事——**变异检查**（把关键判断改反，测试必须红）+ **边界用例**（空值、超长、畸形类型）。AI 写的代码最容易在"看起来该处理但其实没处理"的边界上出问题，比如这次的 `if raw else` 把 `0` 吃掉了。

## 三、30 秒答案集

1. **第三方 API 结构不可信怎么办？** 在客户端那层用 pydantic 模型挡住，`model_validate` 失败抛自己的领域异常。`Any` 只存在于 `resp.json()` 那一行。
2. **500 和 400 怎么划？** 4xx 是客户端能改的错（参数、凭证、权限），5xx 是客户端改不了、重试可能有用的错（依赖挂、DB 连不上）。
3. **JWT 载荷 `sub` 不是 UUID，该返回什么？** 401。这是客户端给了坏 token，不是服务端故障；翻成 500 会污染错误率并触发误告警。
4. **`cast` 有运行时开销吗？** 没有，它就是 `return val` 的恒等函数。选不选它不看性能，看"错了什么时候暴露"。
5. **`cast` 和 `assert isinstance` 怎么选？** 只要静态声明用 `cast`（库无注解时）；要真校验、要当场炸用 `assert`。
6. **怎么判断一个库有没有类型？** 有 `py.typed` 或装了 `types-X` 就有，都没有就是全 `Any`；`pip list | grep types-` 一眼看清。
7. **`ignore_missing_imports` 能全局开吗？** 不能。全局会把 `import-not-found`（包名拼错）一起吞掉，静默通过、运行时才 `ModuleNotFoundError`。
8. **`import-untyped` 和 `import-not-found` 区别？** 前者"包在但没类型"（可放行），后者"包都没找到"（必须报）。
9. **改函数返回类型要注意什么？** 所有调用点的假设都变了。改完必须同时跑 mypy（找全量调用点）和 pytest（验行为）。
10. **为什么 `payload["sub"]` 改成模型后挂了？** pydantic 的 `BaseModel` 没实现 `__getitem__`，属性访问要用 `payload.sub`。
11. **JWT 的 `exp` 是什么类型？** NumericDate，Unix 秒的 `int`。签发能塞 `datetime`，解码回来是 `int`，两个方向不能共用一套类型。
12. **怎么处理时钟偏移？** jose 的 `leeway` 给几十秒容差，但根治靠 NTP；签发与校验机器时钟不一致时宁可放宽 leeway。
13. **覆盖率 96% 说明什么？** 说明 96% 的行被执行过，不说明对不对。真正有用的是 `Missing` 列——那是指向"从没验证过的代码"的地图。
14. **覆盖率 100% 还会漏什么？** 漏逻辑错（都被执行了但判断写反）。补变异测试：把判断改反，测试必须红。
15. **无类型 SDK 怎么接？** 写 wrapper，`cast` 全集中在里面，业务层只见强类型接口；配边界测试，因为静态检查这条链路是空的。

## 四、白板手写靶

### 靶 1：边界校验模型 + 异常翻译（LLM 响应）

```python
class _Message(BaseModel):
    content: str


class _Choice(BaseModel):
    message: _Message


class _ChatCompletion(BaseModel):
    choices: list[_Choice]


data = resp.json()
try:
    parsed = _ChatCompletion.model_validate(data)
except ValidationError as exc:
    raise LLMResponseError("LLM 响应结构不符合预期") from exc
if not parsed.choices:
    raise LLMResponseError("LLM 响应 choices 为空")
return parsed.choices[0].message.content
```

**要点**：`from exc` 不能漏；空列表要单独判（`model_validate` 不检查长度）。

### 靶 2：mypy 配置（精确放行无类型库）

```toml
[tool.mypy]
python_version = "3.11"
strict = true
mypy_path = "src"
explicit_package_bases = true

[[tool.mypy.overrides]]
module = ["jose.*"]
ignore_missing_imports = true
```

**要点**：`module` 必须带 `.*`，否则子模块不生效；全局不写 `ignore_missing_imports`。

### 靶 3：JWT 两段式解码（签名 + 载荷结构分别捕）

```python
try:
    raw = jwt.decode(token, settings.secret_key, algorithms=[settings.algorithm])
except JWTError as exc:
    raise UnauthorizedError("凭证无效或已过期") from exc

try:
    return TokenClaims.model_validate(raw)
except ValidationError as exc:
    raise UnauthorizedError("凭证载荷不合法") from exc
```

**要点**：两个 try 不能合成一个——`JWTError` 和 `ValidationError` 是两类完全不同的失败（签名错 vs 结构错）。

## 五、踩坑实录

| 坑 | 现象 | 教训 |
|---|---|---|

## 六、可以讲成故事的三段

### 故事 1：一个本该 401 的请求返回了 500

背景：`deps.py` 里有 `user_id = UUID(str(sub))`，而 `sub` 来自 JWT 载荷，类型是 `Any`——因为 `decode_access_token` 返回 `dict[str, Any]`。

我以为是：载荷里塞什么都会被 `UUID()` 处理，最坏是抛个异常。

实际是：`UUID("not-a-uuid")` 抛 `ValueError`，没人接，冒到 FastAPI 顶层 → **500**。于是一个"客户端拿了坏 token"的场景，被报成了服务端故障——告警响、错误率涨、SRE 半夜爬起来查一个不存在的 bug。

教训：**载荷是外部数据，不是可信输入**。现在 `TokenClaims.sub: str` 必填 + `model_validate` 校验结构，`deps.py` 里 `except ValueError → UnauthorizedError` 兜住格式，两条测试分别钉住"缺 sub"和"sub 非 UUID"都必须 401。

### 故事 2：我以为 override 是给"有类型的库"加配置

背景：`pyproject.toml` 里原来有两条 override，`jose.*` 和 `passlib.*`，任务是"收窄到只留必要的"。

我以为是：passlib 是老库、jose 是新库，老的才需要兜底，所以删 `jose.*`、留 `passlib.*`。

实际是：完全反了。`passlib` 装了 `types-passlib`，mypy 能看见完整签名，**不需要** override；`jose` 一个 stub 都没有，删掉就立刻报 `import-untyped`。判别不看库的新旧、不看名字，只看**它有没有类型信息**。

教训：配置不是靠猜的。`pip list | grep types-` 三十秒能查清的事，别用直觉投票——**而且 mypy 会当场打脸，前提是你真的跑了它**。

### 故事 3：我自己写下了一句错的注释

背景：`create_access_token` 里原来有 `cast(str, jwt.encode(...))`，注释解释"为什么用 cast 不用 str()"。

我以为是：既然函数签名已经写了 `-> str`，`Any` 赋给 `str` 是合法的，那 cast 就是多余的，顺手把注释改成了"签名已承担声明，不需要 cast"。

实际是：mypy strict 的 `no-any-return` 专门拦这个——"return 一个 `Any`"和"把 `Any` 赋给 `str` 变量"是两件事，前者报错、后者放行。用户照我说的删掉 cast 之后，门禁立刻挂。

教训：**注释是代码的一部分，写错注释等于埋一个坑**。而且这件事暴露了更根本的一点：`cast` 该不该有，取决于"缺口来自库还是来自数据"——库的返回值必须收敛（no-any-return 会逼你），数据的值必须校验（cast 会躲开检查）。
