# D4 · 第三方库边界：Any 从哪进来，怎么关在门外

> 本教材面向"对 mypy 已经会跑、但没系统处理过第三方库"的读者。
> 每个结论都在本项目锁定的 Python 3.11 + 当前 venv 里实测过，命令输出原样贴出。
> 读法：§0–§6 是正文，建议今天读完；§7–§12 是任务、速查、面试、自测，明天做。

## §0 痛点：类型检查在你自己的代码里很严，出了国境就没人管

到 D3 结束，项目里 `mypy --strict` 是 **48 files / 0 error**。你大概会以为"这个项目是类型安全的"。

不是。看这一行（`src/kb_service/core/security.py` 第 43 行）：

```python
payload: dict[str, Any] = jwt.decode(
    token, settings.secret_key, algorithms=[settings.algorithm]
)
```

`jwt` 是第三方库 `python-jose`。它没有类型信息，mypy 眼里它的每个函数都返回 `Any`。

`Any` 的特殊之处：**它可以被当成任何类型使用，而且不产生任何检查**。所以下面这段代码，mypy 一声不响：

```python
from jose import jwt

def use(token: str) -> None:
    payload = jwt.decode(token, "k", algorithms=["HS256"])
    n: int = payload["sub"]                 # 实际是 str，赋给 int，不报
    total = payload["exp"] - "abc"          # int 减 str，不报
    payload["whatever"]["deep"]["x"] = 1    # 结构随便编，不报
```

实测（`mypy --strict --ignore-missing-imports`）：

```
Success: no issues found in 1 source file
```

三行全是运行时必炸的代码，静态检查全绿。这就是"出国境"的代价：**你的代码有类型，第三方库的返回值是黑洞，黑洞会顺着赋值一路传染进你的代码**。

这一天的目标只有一句话：

> **把 `Any` 关在边界上。边界之内，一个 `Any` 都不许流进来。**

不是"消灭第三方库"，也不是"给所有库写 stub"，而是：**在每个跨出自己代码的地方做一次收口**（鉴权、外部 HTTP、配置、数据库驱动……），收口之后内部全是强类型。

## §1 五分钟：先亲眼看见 Any

不进项目，单独建一个文件，跑一次 `reveal_type`。`reveal_type(x)` 是 mypy 的内置调试函数，它会让 mypy 在报告里打印 `x` 被推断成什么类型——运行时它什么都不做。

```python
# probe.py
from __future__ import annotations

from jose import jwt

token = jwt.encode({"sub": "u-1"}, "k", algorithm="HS256")
reveal_type(token)
```

```powershell
# Windows PowerShell

& .\.venv\Scripts\python.exe -m mypy --strict --ignore-missing-imports ..\probe.py
```

```bash

cd /c/Users/acer-pc/WorkBuddy/2026-10-20-08-44-29/python-backend-roadmap/kb-service

```

真实输出：

```
probe.py:6: note: Revealed type is "Any"
Success: no issues found in 1 source file
```

`jwt.encode` 明明运行时返回 `str`，mypy 说 `Any`。

如果**不加** `--ignore-missing-imports`，同一个文件会多出一条错误：

```
probe.py:2: error: Library stubs not installed for "jose"  [import-untyped]
probe.py:2: note: Hint: "python3 -m pip install types-python-jose"
probe.py:2: note: (or run "mypy --install-types" to install all missing stub packages)
probe.py:2: note: See https://mypy.readthedocs.io/en/stable/running_mypy.html#missing-imports
probe.py:6: note: Revealed type is "Any"
Found 1 error in 1 file (checked 1 source file)
```

**这两条输出合起来就是 D4 的全部主题**：

- 不加 ignore → 报 `import-untyped`（mypy 在喊"这个库我没类型信息"）
- 加了 ignore → 不报，但整个库变成 `Any`（mypy 闭嘴，检查也一起没了）

所以 `ignore_missing_imports` 不是"修好"，是"关掉"。关掉之后要**自己补上**检查，这才是 D4 要练的手艺。

## §2 第三方库的三种类型状态

不是所有库都一样。装之前先分三类，处理方式完全不同。

### 2.1 第一类：库自己带类型（`py.typed` 标记）

PEP 561 规定：库如果在包里放一个空的 `py.typed` 文件，等于声明"我的内联注解是真的，请按它检查"。这类库 mypy 直接能用，不需要任何配置。

实测本项目依赖：

| 库 | `py.typed` | 结论 |
|---|---|---|
| `fastapi` | 有 | 直接可用 |
| `pydantic` | 有 | 直接可用 |
| `httpx` | 有 | 直接可用 |
| `jose` | **无** | 无类型 |
| `passlib` | **无** | 无类型（但有独立 stub 包，见 2.2） |

检查某个库有没有，一条命令：

```powershell
# Windows PowerShell
& .\.venv\Scripts\python.exe -c "import jose, os; print(os.path.exists(os.path.join(os.path.dirname(jose.__file__), 'py.typed')))"
```

```bash
# Git Bash / Linux / macOS
./.venv/Scripts/python.exe -c "import jose, os; print(os.path.exists(os.path.join(os.path.dirname(jose.__file__), 'py.typed')))"
```

（输出 `False`。）

### 2.2 第二类：库没类型，但社区写了独立 stub 包

stub 包（也叫"类型桩"）是一个**只有类型声明、没有实现**的包，命名规则是 `types-<库名>`，比如 `types-passlib`、`types-requests`。装进 venv 后，mypy 会用它替代真库来做检查。

本项目 `pyproject.toml` 的 dev 依赖里就有 `types-passlib`。装上之后，`passlib` 从 `Any` 变成了真类型。实测 `reveal_type`：

```python
from passlib.context import CryptContext
from jose import jwt

ctx = CryptContext(schemes=["bcrypt"], deprecated="auto")
reveal_type(ctx.hash)
reveal_type(ctx.verify)
reveal_type(jwt.encode)
reveal_type(jwt.decode)
```

真实输出：

```
d1.py:6: note: Revealed type is "def (secret: str | bytes, scheme: str | None =, category: str | None =, **kwds: Any) -> str"
d1.py:7: note: Revealed type is "def (secret: str | bytes, hash: str | bytes | None, scheme: str | None =, category: str | None =, **kwds: Any) -> bool"
d1.py:8: note: Revealed type is "Any"
d1.py:9: note: Revealed type is "Any"
```

看清楚这个对比：**同一个文件里，`passlib` 有完整签名（参数类型、返回 `str`/`bool` 都明确），`jose` 全是 `Any`。** 差别不在你的代码，在"这个库有没有类型信息"。

> 顺带一个结论（后面 §7 要用）：既然 `passlib` 已经有 stubs 了，项目 `pyproject.toml` 里那条
> `module = ["passlib.*", "jose.*"]` 的 `ignore_missing_imports` 覆盖，**对 passlib 就是多余的**。
> 实测把 passlib 从 override 里删掉，`mypy src tests scripts conftest.py` 仍然 `Success: no issues found in 48 source files`。

### 2.3 第三类：库没类型，也没有 stub 包

`jose` 就是。mypy 会给 `import-untyped`（装了但没类型），如果**连包都没装**则是 `import-not-found`（找不到模块）。

两种错误码不同，但都可以被 `ignore_missing_imports` 吞掉——这就是 §4 要讲的危险。

## §3 Any 的传染链：`warn_return_any` 只挡第一层

很多人以为开了 `--strict` 就没事了，因为 `strict` 里有 `warn_return_any`。实测看它到底挡什么：

```python
# a1.py
from jose import jwt

def subject_of(token: str) -> int:      # 声明返回 int
    return jwt.decode(token, "k", algorithms=["HS256"])["sub"]   # 实际是 str

def count_of(token: str) -> int:
    return jwt.decode(token, "k", algorithms=["HS256"]).get("n")
```

```
a1.py:5: error: Returning Any from function declared to return "int"  [no-any-return]
a1.py:8: error: Returning Any from function declared to return "int"  [no-any-return]
Found 2 errors in 1 file (checked 1 source file)
```

它抓到了——但只在**"把 Any 当作返回值直接返回"**这一种形状上。换成"先取出来、再赋给有类型的变量"，就完全失效（就是 §0 那段 `a2.py`）：`Success: no issues found`。

也就是说 `warn_return_any` 是一道**只拦大门的栅栏**：`return <Any>` 会被拦，`x: int = <Any>`、`<Any> - "abc"`、`<Any>["k"]["deep"]` 全都放行。

所以真正可靠的做法不是"靠 warn_return_any 兜底"，而是**别让 Any 生出来**——在边界处就转成确定类型。

## §4 `ignore_missing_imports` 的三种粒度，代价各不相同

同一个开关，写在哪，代价差一个数量级。

### 4.1 全局：`ignore_missing_imports = true`

```ini
[mypy]
strict = True
ignore_missing_imports = True
```

这是最常见的"网上一搜就这么写"的配置。它的实际效果：**所有 import 失败都不再报错**，包括"根本没这个包"和"包名打错了"。

实测。文件里库名多打一个 `x`：

```python
# b2.py
import httpxx
print(httpxx)
```

- 精确配置（只忽略 jose）：

```
b2.py:2: error: Cannot find implementation or library stub for module named "httpxx"  [import-not-found]
b2.py:2: note: Did you mean "httpx"?
Found 1 error in 1 file (checked 1 source file)
```

- 全局 `ignore_missing_imports = True`：

```
Success: no issues found in 1 source file
```

运行时报什么？`ModuleNotFoundError: No module named 'httpxx'`。

拼错库名这种错误**还好**，因为它一 import 就炸。真正贵的是另一种：拼错的是**不常执行路径上的 import**（比如某个只在周末跑的数据修复脚本、某个只在异常分支里 import 的库），错误会潜伏到线上才爆发。静态检查的价值本来就是把这类错误提前，全局忽略等于把它关掉。

**结论：不要用全局 `ignore_missing_imports`。**

### 4.2 模块级 override：只放行确实没类型的那个库

本项目实际用的是这个（`pyproject.toml`）：

```toml
[[tool.mypy.overrides]]
module = ["passlib.*", "jose.*"]
ignore_missing_imports = true
```

效果：只有 `passlib` / `jose` 开头的模块被放行，别的 import 拼错照样报。§4.1 那个 `httpxx` 在这个配置下会正常报 `import-not-found`。

粒度对了，但还有两个问题：

1. **面还是偏大**：`passlib.*` 是多余的（§2.2 实测过），应该收窄成只有 `jose.*`
2. **放行 = 该库全变 Any**：mypy 不再检查任何一行涉及 `jwt.encode` / `jwt.decode` 的代码。这个代价必须用 §5 的"边界收口"补回来

### 4.3 行内：`# type: ignore[import-untyped]`

也可以不动配置，只在 import 那一行加注释：

```python
import httpxx  # type: ignore[import-not-found]
```

实测：`Success`。这种方式的好处是**精确到行**、还能被 `warn_unused_ignores` 管住（哪天装了 stub，这行 ignore 会变成 `unused-ignore` 报错，提醒你删掉）。

坑在**错误码**。把码写成 `import-untyped`（"有类型问题的库"）而实际是"找不到模块"，实测会报两条：

```
b4.py:2: error: Unused "type: ignore" comment  [unused-ignore]
b4.py:2: error: Cannot find implementation or library stub for module named "httpxx"  [import-not-found]
b4.py:2: note: Error code "import-not-found" not covered by "type: ignore[import-untyped]" comment
```

也就是说 ignore 不是"万能消音器"，**它必须点名要消哪个错误码**，点错了照样报，而且会额外告诉你"你这条 ignore 没起作用"。这是 `--strict`（含 `warn_unused_ignores`）带来的好处：**ignore 是有账的**。

### 4.4 三粒度怎么选

| 粒度 | 适合 | 代价 |
|---|---|---|
| 全局 | 基本不该用（除非遗留项目一次性过渡） | 拼错库名静默通过，运行时才炸 |
| 模块 override | 项目里固定几个无类型库（本项目的选择） | 该库范围内全 `Any`，要在边界补校验 |
| 行内 ignore | 临时、单点、想被 `unused-ignore` 管住 | 散落各处，多了没人管 |

**本项目的选择是"模块 override + 边界收口"**：override 让 mypy 闭嘴，收口让类型回来。

## §5 核心手艺：边界收口（把 Any 关在门外）

### 5.1 先看清一个不对称：encode 和 decode 的字段类型不一样

这是今天最反直觉、也最值钱的一条。`create_access_token` 里我们塞进去的是 `datetime`：

```python
payload = {
    "sub": subject,
    "iat": now,                                        # datetime
    "exp": now + timedelta(minutes=...),               # datetime
}
```

拿回来是什么？实测：

```python
payload = {"sub": "u-1", "iat": datetime.now(UTC), "exp": datetime.now(UTC) + timedelta(minutes=30)}
tok = jwt.encode(payload, "secret", algorithm="HS256")
back = jwt.decode(tok, "secret", algorithms=["HS256"])
for k, v in back.items():
    print(f"  {k}: {type(v).__name__} = {v!r}")
```

真实输出：

```
decode 回来的对象: {'sub': 'u-1', 'iat': 1793596486, 'exp': 1793598286}
  sub: str = 'u-1'
  iat: int = 1793596486
  exp: int = 1793598286
```

**进去是 `datetime`，出来是 `int`（Unix 秒）。** 因为 JWT 的 `exp`/`iat` 标准（RFC 7519）规定用 NumericDate，`python-jose` 帮你转成了秒数。

推论很直接：**不要用同一个类型给"签发"和"解析"两个方向做契约**。如果你写一个 `TokenPayload` 声明 `exp: datetime` 然后在 decode 之后用它，那条契约就是假的——`payload["exp"]` 实际是 `int`，任何 `payload["exp"] > datetime.now()` 都会 `TypeError`。

### 5.2 用 pydantic 在边界做一次运行时校验

`Any` 关不掉的原因是：mypy 不知道 JWT 里到底有什么。既然静态不知道，就让**运行时**验证一次，验证完就是强类型。

```python
# src/kb_service/core/security.py
from pydantic import BaseModel, ValidationError


class TokenClaims(BaseModel):
    """JWT 载荷的业务契约（decode 之后的方向）。

    注意 exp/iat 在 decode 后是 Unix 秒（int），不是 datetime ——
    编码方向塞 datetime，解码方向拿回来 int，两个方向不能共用一套类型。
    """

    sub: str
    iat: int | None = None
    exp: int | None = None
```

然后：

```python
def decode_access_token(token: str) -> TokenClaims:
    settings = get_settings()
    try:
        raw = jwt.decode(token, settings.secret_key, algorithms=[settings.algorithm])
    except JWTError as exc:  # 过期 / 签名错 / 格式错，统一按未认证处理
        raise UnauthorizedError("凭证无效或已过期") from exc
    try:
        return TokenClaims.model_validate(raw)
    except ValidationError as exc:
        raise UnauthorizedError("凭证载荷不合法") from exc
```

调用方拿到的是 `TokenClaims`，`claims.sub` 一定存在、一定是 `str`——**这是运行时保证的，不是 cast 声明的**。

### 5.3 这个校验到底挡了什么：五种坏载荷实测

```python
cases = {
    "正常": {"sub": "u-1", "iat": 1, "exp": 2},
    "带额外 claim": {"sub": "u-1", "iat": 1, "exp": 2, "role": "admin"},
    "sub 是 int": {"sub": 123},
    "缺 sub": {"iat": 1},
    "exp 是日期字符串": {"sub": "u", "exp": "2026-11-02T00:00:00"},
}
```

真实输出：

```
正常               -> ok  sub='u-1' exp=2 额外字段保留=None
带额外 claim        -> ok  sub='u-1' exp=2 额外字段保留=None
sub 是 int        -> ValidationError(1): Input should be a valid string
缺 sub            -> ValidationError(1): Field required
exp 是日期字符串       -> ValidationError(1): Input should be a valid integer, unable to parse string as an integer
```

三条结论：

1. **`sub: str` 真的挡得住 int**——pydantic v2 默认不做 int→str 的宽松转换，`123` 直接拒。
2. **缺键挡得住**——`Field required`，不需要你在下游写 `if "sub" not in payload`。
3. **额外字段被静默丢弃**（`额外字段保留=None`）。因为 pydantic 默认 `extra='ignore'`。对 JWT 来说通常是对的（我们只关心 `sub`），但**如果哪天要把 token 里的 `role` 往下传，它会静默消失**——那时要么加显式字段，要么 `model_config = ConfigDict(extra="allow")`。

### 5.4 反例：类型对了，业务契约还是漏了（一个真 bug）

`decode_access_token` 现在保证 `sub` 是 `str`。但"是字符串"不等于"是合法用户 ID"。原来的 `deps.py`：

```python
payload = decode_access_token(credentials.credentials)
sub = payload.get("sub")
if not sub:
    raise UnauthorizedError("凭证缺少 subject")
return UUID(str(sub))     # ← 这里
```

如果有人拿到密钥（或你自己签发时手滑）签了一个 `sub="not-a-uuid"` 的 token，`UUID(str(sub))` 抛 `ValueError`。`ValueError` 不在业务异常体系里，FastAPI 的异常处理器不认它 → **500**。

实测（`create_access_token("not-a-uuid")` 之后请求 `GET /api/v1/kbs`）：

```
status: 500
body: Internal Server Error
```

日志里能看到完整栈：`ValueError: badly formed hexadecimal UUID string`，位置 `deps.py:41`。

**这就是"边界没做完"的典型形状**：类型层已经收口了（`sub: str` 通过），但**业务层的约束（必须能解析成 UUID）没人管**。修法是把这一层也收口：

```python
claims = decode_access_token(credentials.credentials)
try:
    return UUID(claims.sub)
except ValueError as exc:
    raise UnauthorizedError("凭证 subject 不是合法用户 ID") from exc
```

认证失败必须是 401，不是 500。这个区别在面试里经常被追问（"token 伪造的请求，你的服务返回什么？"）。

## §6 外部 HTTP 返回 JSON：`cast` 和 `model_validate` 的实战对比

`httpx` 有类型，但 `Response.json()` 的签名是 `def json(self) -> Any`。这不是 httpx 的锅——**JSON 里是什么结构，只有运行时才知道**。所以任何 HTTP 客户端都会在这一点上返回 `Any`。

本项目现在这么写（`services/llm_client.py:46`）：

```python
return cast(str, resp.json()["choices"][0]["message"]["content"])
```

`cast(str, ...)` 的语义是"我担保它是 str，别检查了"。担保错了会怎样？实测三种响应：

```python
def with_cast(payload):  return cast(str, payload["choices"][0]["message"]["content"])
def with_model(payload): return ChatCompletion.model_validate(payload).choices[0].message.content
```

真实输出：

```
正常             with_cast   -> 'RAG 是检索增强生成。'
正常             with_model  -> 'RAG 是检索增强生成。'
缺 content      with_cast   -> KeyError: 'content'
缺 content      with_model  -> ValidationError: 1 validation error for ChatCompletion
choices.0.message.cont
content 是 int  with_cast   -> 123
content 是 int  with_model  -> ValidationError: 1 validation error for ChatCompletion
choices.0.message.cont
```

**关键在最后两行**：

- `cast` 遇到 `content: 123` 直接**返回 `123`**——一个 `int`，被声明成 `str` 传出去了。函数签名说 `-> str`，调用方拿到 `int`，之后 `.strip()`、`len()`、写数据库全看运气。
- `model_validate` 报 `ValidationError`，错误信息里直接指出路径 `choices.0.message.content`。

`cast` 还带来一个副作用：它是"零运行时开销的纯声明"，所以**错误被推迟到很远的地方**。而 `model_validate` 是"在边界处立刻失败"——**越早失败越便宜**，这是工程上的一般原则（fail fast）。

正确的写法：

```python
# src/kb_service/services/llm_client.py
from pydantic import BaseModel, ValidationError


class _Message(BaseModel):
    content: str


class _Choice(BaseModel):
    message: _Message


class _ChatCompletion(BaseModel):
    choices: list[_Choice]


class LLMResponseError(RuntimeError):
    """LLM 返回的结构不符合 OpenAI 兼容协议。"""
```

```python
data = resp.json()          # Any —— 边界在这里
try:
    parsed = _ChatCompletion.model_validate(data)
except ValidationError as exc:
    raise LLMResponseError("LLM 响应结构不符合预期") from exc
if not parsed.choices:
    raise LLMResponseError("LLM 响应 choices 为空")
return parsed.choices[0].message.content
```

注意 `if not parsed.choices` 这行：**类型系统只能保证"`choices` 是 `list[_Choice]`"，不能保证"非空"**。`list[Choice]` 允许空列表，`[0]` 就是 `IndexError`。这类"长度/范围约束"永远归运行时管——这也是为什么 §5.4 的 UUID 校验必须手写。

### 6.1 什么时候 `cast` 仍然是对的

不是所有 `cast` 都该消灭。判断标准：**你有没有能力在这一行之前把它验证掉**。

- 能验证（有数据在手、有 schema）：用 `model_validate` / 手写 `isinstance` 检查，别用 `cast`
- 不能验证（类型系统表达力不够，比如 `cast("dict[str, Any]", row).update(payload)` 那种 D3 见过的场景）：用 `cast`，并在注释里写清"为什么这里只能担保"

D3 总结里那条"cast 登记制"就是为这个准备的：**每一处 cast 都要能回答"为什么不能校验"**。

## §7 治理：让"无类型"变成一份有账的清单

### 7.1 `disallow_any_expr` 为什么不能开

mypy 有个更狠的开关 `--disallow-any-expr`（"任何 Any 表达式都报错"）。听起来正是我们想要的，实测一下：

```python
def sub_of(token: str) -> str:
    claims = jwt.decode(token, "k", algorithms=["HS256"])
    return str(claims["sub"])
```

```
e1.py:5: error: Expression has type "Any"  [misc]
e1.py:6: error: Expression has type "Any"  [misc]
Found 2 errors in 1 file (checked 1 source file)
```

它确实抓到了——**但它抓的是"你碰了 Any"这件事本身，不是"你用错了"**。`claims = jwt.decode(...)` 这一行是不可避免的（你总得调用它），所以这个开关在没有 stub 的库面前等于"禁止使用该库"。在一个真实项目里开它，噪音会淹掉真正的错误。

结论：`disallow_any_expr` 适合库作者自己检查，不适合业务项目。业务项目的正确姿势是**收口 + 局部 ignore**。

### 7.2 pydantic 的 mypy 插件：第三方也能"扩展"类型检查器

项目 `pyproject.toml` 里有这一行：

```toml
plugins = ["pydantic.mypy"]
```

插件是 mypy 的扩展点，让第三方库能改变检查行为。pydantic 插件做的事：**让 `Model(field=...)` 的构造调用也被检查**——没有插件时，mypy 只认 `__init__(**data: Any)`，字段名打错也不报；有插件时，`KBCreate(nmae="x")` 会报 `unexpected keyword argument`。

这条也是 D1 那 58 个错误里 `config.py:45` 那个"过期 `# type: ignore[call-arg]`"的由来：**装了插件之后，原来必须 ignore 的地方不再需要 ignore**，于是 ignore 变成 `unused-ignore`。插件的存在本身会改变历史结论——所以升级依赖后要重跑一遍门禁。

## §9 易错点表

| 坑 | 症状 | 正解 |
|---|---|---|
| 用全局 `ignore_missing_imports` | 拼错库名静默通过，运行时 `ModuleNotFoundError` | 模块级 override，只放行确实无类型的库 |

| 开了 `disallow_any_expr` | 一碰无类型库就报，噪音淹没真错误 | 业务项目别开，用收口 + 局部 override |

## §11 面试问法

### Q1：你们项目怎么处理没有类型标注的第三方库？

**30 秒版**：分三种情况。库自带 `py.typed` 就直接用；没有但有社区 stub（`types-xxx`）就装 stub；都没有才用 `ignore_missing_imports`，而且**只对那个模块开**，不开全局——全局会把"库名拼错"一起吞掉。放行之后必须在边界做运行时校验，把 `Any` 收口成具体类型，不然静态检查那一块等于没有。

**追问链**：
1. 为什么不直接 `cast`？→ cast 是纯声明，错了没人拦，错误被推迟到使用点。实测 `cast(str, 123)` 会原样返回 `int`。
2. `ignore_missing_imports` 全局和模块级差在哪？→ 全局连 `import-not-found` 都吞，拼错库名静默通过。
3. 边界校验用 pydantic 会不会太慢？→ JWT 解析一次几十微秒，pydantic 校验同一量级，相比一次 DB 查询可忽略；而且换来的是一次性的结构保证。

### Q2：JWT 的 payload 你怎么建模？

**30 秒版**：用一个 pydantic 模型声明业务契约（`sub: str`），decode 之后立刻 `model_validate`，失败转 401。关键细节是 **encode 和 decode 的字段类型不对称**：塞进去 `datetime`，拿出来是 Unix 秒 `int`，因为 RFC 7519 规定 NumericDate。所以不能给两个方向共用一套类型，我这边解码方向的模型里 `exp` 声明成 `int`。

**追问链**：
1. 那 `sub` 校验成 `str` 就够了吗？→ 不够。`sub: str` 只保证是字符串，业务上要求是 UUID，`UUID(sub)` 失败必须转 401 而不是让 `ValueError` 冒到 500。
2. token 被伪造的请求，你的服务返回什么？→ 401，统一走 `UnauthorizedError`。500 是"我的代码有 bug"，401 是"你没权限"，混在一起会污染监控指标。
3. 额外 claim 怎么处理？→ pydantic 默认 `extra='ignore'`，会静默丢弃；要往下传就得显式声明字段或 `extra="allow"`。

### Q3：HTTP 客户端返回 JSON，你怎么保证结构？

**30 秒版**：`resp.json()` 天生 `Any`——JSON 结构运行时才知道，任何客户端都这样。我的做法是用 pydantic 模型 `model_validate`，结构不对在边界就抛 `LLMResponseError`。绝不 `cast`，因为 `cast` 遇到 `content: 123` 会原样返回 `int`，函数签名说 `str` 但调用方拿到 `int`，之后随便一个字符串方法就炸，而且堆栈指向很远，排查成本高。这是 fail fast 的应用。

**追问链**：
1. 模型校验有性能成本吗？→ 有，但相比一次网络往返可以忽略；真正的成本在"错误延迟暴露"上，那个更贵。
2. 上游 API 加字段会不会让你的代码挂？→ 不会，`extra` 默认忽略。但上游**改**字段类型（比如 `content` 变对象）会挂，这正是我们想要的：立刻失败，而不是拿着错数据往下跑。
3. 空 `choices` 怎么处理？→ 类型系统只能保证是 list，不能保证非空，显式判空抛错。

## §12 闭卷自测（10 题，答案折叠）

<details>
<summary>1. `py.typed` 是干什么的？没有它会怎样？</summary>

PEP 561 的标记文件，声明"这个包的内联注解是真的"。没有它，mypy 把该包当成无类型第三方库，直接跳过分析（`import-untyped` / `Skipping analyzing`），所有符号变 `Any`。
</details>

<details>
<summary>2. `import-untyped` 和 `import-not-found` 有什么区别？</summary>

`import-untyped`：包装了但没有类型信息。`import-not-found`：压根找不到这个模块（没装，或名字拼错）。两个都会被 `ignore_missing_imports` 吞掉，但 `# type: ignore[code]` 里必须写对码，否则报 `unused-ignore` + `not covered by`。
</details>

<details>
<summary>3. 为什么全局 `ignore_missing_imports = true` 是坏配置？</summary>

它把"找不到模块"也一起忽略了。实测 `import httpxx`（多打一个 x）在全局配置下 `Success`，运行时 `ModuleNotFoundError`。静态检查本来该提前抓的错，被配置关掉了。
</details>

<details>
<summary>4. `warn_return_any` 能挡住 Any 传染吗？边界在哪？</summary>

只能挡"把 Any 直接当返回值返回"（`Returning Any from function declared to return "int"`）。`x: int = <Any>`、`<Any> - "abc"`、`<Any>["k"]["deep"]` 全部放行。所以它是栅栏不是墙。
</details>

<details>
<summary>5. JWT encode 时传 `datetime`，decode 回来是什么？为什么？</summary>

`int`（Unix 秒）。RFC 7519 规定 `exp`/`iat` 用 NumericDate（自 1970 起的秒数），`python-jose` 编码时自动转换。所以解码方向的模型必须声明 `int`，声明 `datetime` 是假契约。
</details>

<details>
<summary>6. `cast(str, x)` 和 `ChatCompletion.model_validate(x)` 的本质区别？</summary>

`cast` 是编译期纯声明，零运行时行为，错了不拦；`model_validate` 是运行时真校验，错了抛 `ValidationError` 并带路径。前者把错误推迟，后者在边界立刻失败。
</details>

<details>
<summary>7. 为什么 `cast` 有时仍然该用？判断标准是什么？</summary>

标准是"这一行之前你有没有能力验证"。能验证（有数据、有 schema）就不该 cast；不能验证（类型系统表达力不够，如 `cast("dict[str, Any]", row).update(payload)`）才 cast，并且注释里写清理由——这就是 cast 登记制。
</details>

<details>
<summary>8. pydantic 默认会保留 JWT 里的额外 claim 吗？</summary>

不会。默认 `extra='ignore'`，实测 `model_extra` 是 `None`。需要保留就显式声明字段，或 `model_config = ConfigDict(extra="allow")`。
</details>

<details>
<summary>9. `sub: str` 校验通过，为什么接口还可能 500？</summary>

类型对了不等于业务合法。`sub` 是字符串但可能不是合法 UUID，`UUID(sub)` 抛 `ValueError`，没被包成业务异常就是 500。正确做法是 `try/except ValueError` → `UnauthorizedError`（401）。
</details>

<details>
<summary>10. 为什么不开 `--disallow-any-expr`？</summary>

它报的是"你碰了 Any"这件事本身。无 stub 的库每次调用都会被报，噪音淹没真错误，等于禁用该库。业务项目用"收口 + 局部 override"更实际；这个开关适合库作者自查。
</details>
