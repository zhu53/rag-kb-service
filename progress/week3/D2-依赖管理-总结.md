# W3-D2 · 依赖管理深入 总结（2026-10-24）

> 教材就是自己的 kb-service：pyproject.toml（愿望）对照 uv.lock（现实）。

## 一、pyproject.toml 四大块

| 块 | 装什么 | 关键点 |
|---|---|---|
| `[project]` | 身份证 + **对外契约**：requires-python + dependencies | 别人装你的包会被自动带上这些 |
| `[dependency-groups]` | 开发者私人工具（pytest/ruff/mypy） | `uv sync` 默认装 dev；生产 `--no-dev` |
| `[build-system]` | 打包方式（hatchling + src 布局） | 决定 `uv sync` 怎么把项目装成可编辑包 |
| `[tool.*]` | ruff/mypy/pytest/coverage 配置 | **单一事实来源**，不再散落多个配置文件 |

## 二、语义化版本与约束

`2.14.1` = 主.次.补丁：**major 变 = 破坏**；minor = 新功能；patch = 修 bug。
**⚠️ 0.x 特例（面试考点）**：0.x 的 minor 允许破坏——`fastapi>=0.115` 实际允许任何未来破坏性更新。

写法：`>=0.115`（下限）· `==0.115.0`（钉死）· `>=1.2,<2.0`（区间）· `~=1.4.2`（1.4.x）。

## 三、愿望 vs 现实（今天核心）

| | pyproject dependencies | uv.lock |
|---|---|---|
| 本质 | **约束**（"fastapi>=0.115"） | **精确解**（"0.150.0 + sha256 + 下载地址"） |
| 范围 | 直接依赖 8 个 | **整棵树 62 个包** |
| 维护 | 手写 | uv 自动生成，**必须进 Git** |
| 价值 | 表达兼容意图 | **跨机器跨时间完全复现** |

工作流：`uv add` → lock 重新解算 → 两个文件一起 commit → 别人 `uv sync` 逐字节复现。
CI/生产用 `uv sync --frozen`（lock 与 pyproject 不一致就报错，不偷偷重解算）。
`uv lock --check`：验证两者同步。

**不提交 lock 的后果**：重新解算 → 装到当时最新 → 62 包逐个漂移 → "我机器上能跑"；且失去 hash 校验。

**三个槽位（面试常考）**：
- 运行时必需（sqlalchemy）→ `[project.dependencies]`
- 开发工具（pytest/ruff）→ `[dependency-groups] dev`
- 可选配件（未来可选部署的 redis）→ extras

## 四、extras vs dependency-groups（易混！）

`uvicorn[standard]>=0.32` = **uvicorn 必装** + 勾选它的 standard 可选组
（树里 `(extra: standard)` 标记的 watchfiles/websockets/httptools 就是买到的配件）。

| | extras `包[名字]` | dependency-groups |
|---|---|---|
| 谁提供 | **别人的包** | **你的项目** |
| 给谁 | 使用者按需选 | 只在开发时 |
| 进发布元数据 | 进 | 不进 |

## 五、依赖树三个现象（uv tree 实测）

1. `pydantic` 出现两次、第二处标 `(*)`——**多方依赖只装一份**，解算器保证全局单版本
2. `starlette` 挂在 fastapi 下——**FastAPI 是 starlette 的上层封装**（W6 主线伏笔）
3. extras 在树里肉眼可见兑现：`(extra: standard)` / `(extra: bcrypt)`

## 六、闭卷快问（折叠）

<details><summary>1. pyproject 和 uv.lock 各锁什么？</summary>pyproject 锁兼容范围（愿望），uv.lock 锁全树精确版本+hash（现实）；复现性靠 lock 进 Git。</details>
<details><summary>2. 0.x 版本号 >= 约束的风险？靠什么兜底？</summary>0.x minor 允许破坏；日常靠 lock 钉住，升级时主动 uv lock --upgrade + 跑测试。</details>
<details><summary>3. dependency-groups 和 extras 的区别？</summary>前者是你项目的开发工具（不进发布元数据），后者是别人的包提供的可选配件（进元数据）。</details>
<details><summary>4. 为什么 62 个包里 pydantic 只装一份？</summary>版本解算器全局一致——多方依赖同一个包时解出共同满足的单一版本。</details>
<details><summary>5. uv sync --frozen 是干什么的？</summary>严格按 lock 装不重新解算；lock 与 pyproject 不同步就报错——CI/生产防漂移。</details>
